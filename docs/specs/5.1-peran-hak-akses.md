# 5.1 Peran & hak akses (Owner / Admin)

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 5 — Saat admin mulai input | P2 | L | 0.1 (`created_by`) | K4 |

## Tujuan

Staf admin bisa mencatat transaksi harian (POS, order, pembayaran, biaya job, customer, servis) **tanpa** melihat margin, HPP, laporan, modal & bagi hasil, dan tanpa bisa menghapus catatan uang. Dua peran saja — owner dan admin — dengan aturan tetap di kode.

Jangan dimulai sebelum owner memastikan ada staf yang akan input (lihat `docs/rencana-pengembangan-operasional.md` peta fase).

## Lingkup

**Termasuk**
- Kolom `users.role` + enum, Gate, middleware di route, pembersihan props finansial di server, penyaringan sidebar, halaman Settings → Pengguna untuk owner.
- Command `app:buat-pengguna` menerima peran.

**Tidak termasuk**
- Tabel permission / peran dinamis — dua peran hard-coded (`// ponytail: dua peran hard-coded; tabel permission kalau peran ketiga muncul`).
- Pembatasan per data (admin hanya melihat order yang dia catat) — semua admin melihat semua catatan operasional.
- Audit siapa mengubah peran — cukup `created_by`/`updated_at` di `users` (jumlah user < 5).
- Shift kasir → 5.2.

## Aturan bisnis

1. Setiap user punya tepat satu peran: `owner` atau `admin`. User yang ada saat migrasi → `owner`.
2. **Admin tidak boleh**: membuka Laporan (semua), Modal & Bagi Hasil, halaman Pengguna; melihat `margin`, `direct_cost`, `material_cost`, `unit_cost` (HPP), omzet/BEP Dashboard; menghapus pembayaran, biaya job, biaya operasional, servis aset, setoran/penarikan modal; menambah/mengubah/menonaktifkan katalog; menambah/melepas aset; tutup/buka buku.
3. **Admin boleh**: Dashboard (jadwal, piutang, perawatan jatuh tempo), POS, Order & Booking (buat, lanjut status, batal, link hasil, catat bayar, edit per 1.2), Pembayaran, Customer (tambah/ubah), Katalog (lihat saja, tanpa HPP), Biaya (lihat + catat biaya job; **tidak** biaya operasional — itu uang kas usaha, owner), Aset (lihat + catat servis + ubah status rusak/aktif), Invoice, Komunikasi (lihat template, kirim; **tidak** ubah template).
4. **Owner** = semua yang ada sekarang + mengelola pengguna.
5. Minimal satu owner harus tetap ada: owner tidak bisa menurunkan dirinya sendiri kalau dia owner terakhir, dan tidak bisa menghapus/menonaktifkan dirinya.
6. Props finansial **dihilangkan di server** untuk admin, bukan disembunyikan di klien — klien merender kolom berdasarkan ada-tidaknya field.
7. Gate ditolak → `403` (halaman error standar Inertia), bukan redirect diam-diam; menu yang terlarang tidak tampil sehingga 403 hanya terjadi lewat URL manual.

## Perubahan data

Migrasi `add_role_to_users_table`: `$table->string('role')->default('owner')` setelah `email`. Default `owner` **hanya** untuk mengisi baris lama; pembuatan user baru selalu menyebut peran eksplisit. `down()` → `dropColumn('role')`.

Enum (baru) `App\Enums\UserRole: string { Owner = 'owner'; Admin = 'admin' }` + `label()` ("Owner", "Admin") + `isOwner(): bool`.

`App\Models\User`: `#[Fillable(['name','email','password','role'])]`, cast `'role' => UserRole::class`, `@property UserRole $role`, helper `isOwner(): bool`. `UserFactory` default `role => UserRole::Owner`; state `admin()`.

### Props finansial yang dihilangkan untuk admin

Helper (baru) `Modules\Shared\Support\Finance::visible(): bool` = `Gate::allows('view-finance')`, dipanggil di controller; field dihapus dengan `Arr::except`/kondisi, bukan diisi `null` (supaya klien bisa membedakan "tidak boleh lihat" dari "nol").

| Controller | Field dihilangkan untuk admin |
|---|---|
| `OrderController::orderProps()` | `direct_cost`, `margin`, `job_costs[]` (seluruh daftar — nominal biaya job per order adalah komponen margin) |
| `PosController@index` | `products[].unit_cost` → klien tidak menampilkan HPP/margin keranjang |
| `CatalogItemController@index` | `items[].unit_cost`, `margin_ratio` (3.6) |
| `DashboardController` | `revenue`, `break_even` |
| `ExpenseController@index` | `operating_expenses`, `totals.operating` (biaya operasional = kas usaha); `job_costs` tetap (admin mencatatnya) |
| `AssetController@index` | `summary.book_value`, `summary.allocation`, `assets[].allocation`, `assets[].book_value`, `assets[].accumulated`, `maintenance_balance`, `assets[].funded_by` |
| `CommunicationController@index` | tidak ada (template tetap terbaca) |
| `ReceivableController`, `InvoiceController` | tidak ada — piutang & invoice adalah pekerjaan admin |

### Shared props
`HandleInertiaRequests::share()` → `auth.user` sudah dikirim; tambah `auth.can: { view_finance, manage_catalog, delete_money, close_period, manage_users, manage_assets, manage_templates, record_operating_expense }` (boolean dari Gate) supaya klien tidak menebak dari `role`.

### Route (baru) — Pengguna
`routes/settings.php`, group `['auth','verified','can:manage-users']`:

| Method | Path | Name | Handler |
|---|---|---|---|
| GET | `settings/users` | `users.index` | `App\Http\Controllers\Settings\UserController@index` |
| POST | `settings/users` | `users.store` | `@store` |
| PATCH | `settings/users/{user}` | `users.update` | `@update` (nama, peran, sandi baru opsional) |

Tidak ada `destroy`: user yang keluar diubah jadi… tidak ada status nonaktif di skema; **usulan**: `users.update` menerima `role` saja dan sandi di-reset — akun yang tidak dipakai diganti sandinya oleh owner. Menambah kolom `disabled_at` ditunda sampai perlu (`// ponytail`).

### Request (baru)
- `App\Http\Requests\Settings\StoreUserRequest`: `name` required max:255; `email` required email unique:users; `role` `Rule::enum(UserRole::class)`; `password` required `Password::defaults()` confirmed. Dibuat lewat `CreateNewUser` Fortify (sama dengan `app:buat-pengguna`) lalu `forceFill(['role'=>…, 'email_verified_at'=>now()])`.
- `UpdateUserRequest`: `name`, `role`, `password` nullable confirmed. `withValidator`: menolak menurunkan owner terakhir ("Harus ada minimal satu owner") dan menolak owner mengubah peran dirinya sendiri.

Semua `attributes()` Indonesia: `role` → "peran".

### Command
`app:buat-pengguna` menambah `select('Peran', UserRole::cases())` default Owner.

### Props Inertia

## Frontend

- `app-sidebar.tsx`: `navGroups` menjadi fungsi `navGroupsFor(can)`; item `Laporan` dan `Modal & Bagi Hasil` disertakan hanya bila `can.view_finance`. Grup "Keluaran" tetap ada untuk admin (Invoice, Komunikasi). Vitest untuk fungsi ini.
- `layouts/settings/layout.tsx`: item "Pengguna" (ikon `Users`) hanya bila `can.manage_users`.
- Halaman (baru) `pages/settings/users.tsx`: tabel (nama, email, peran badge, dibuat), tombol "Tambah pengguna" → dialog (nama, email, peran `Select`, sandi + konfirmasi), menu baris "Ubah" (nama, peran, sandi baru opsional). Teks bantuan: "Admin tidak melihat laporan, modal, margin, dan tidak bisa menghapus catatan uang."
- Kolom/bagian kondisional berdasarkan **ada-tidaknya field**:
  - `order/pages/index.tsx` Sheet: `Section "Biaya job & margin"` dirender hanya bila `order.margin !== undefined`; tombol hapus pembayaran hanya bila `can.delete_money`.
  - `pos.tsx`: baris "HPP bahan … · margin …" hanya bila produk pertama punya `unit_cost !== undefined`.
  - `catalog/pages/index.tsx`: kolom HPP & Margin, tombol Tambah/Ubah/Nonaktifkan → `can.manage_catalog`.
  - `expense/pages/index.tsx`: tab Biaya Operasional hanya bila `operating_expenses` ada; tombol hapus → `can.delete_money`.
  - `asset/pages/index.tsx`: kartu nilai buku/alokasi, tombol Tambah Aset/Lepas → sesuai field/`can`.
  - `dashboard.tsx`: kartu Omzet & BEP hanya bila `revenue !== undefined`.
  - `finance/pages/capital.tsx`: tombol hapus → `can.delete_money`; tutup/buka buku → `can.close_period`.
  - `customer/pages/communication.tsx`: form ubah template → `can.manage_templates`.
- Komponen `ConfirmDelete` tidak berubah; pemanggil yang menyembunyikan.
