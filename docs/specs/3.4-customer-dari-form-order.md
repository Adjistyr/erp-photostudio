# 3.4 Customer baru dari form order

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 3 — Skala & jalan pintas harian | P2 | S | 1.2 (`order-form.tsx` bersama), 2.1 (`Phone::normalise()`) | — |

## Tujuan

Form Buat Order mewajibkan `customer_id` yang sudah ada (`StoreOrderRequest`: `required|exists:customers,id`) dan pemilihnya adalah `Select` biasa tanpa pencarian. Customer baru yang deal lewat chat memaksa admin ke menu Customer → simpan → kembali → cari di dropdown. POS sudah bisa membuat customer dari nama (`PosController::customerFor`); form order harus setara.

## Lingkup

**Termasuk**
- `customer_id` **atau** `new_customer {name, phone}` di `StoreOrderRequest` dan `UpdateOrderRequest` (1.2).
- Pembuatan customer di dalam transaksi `OrderController@store`/`@update`, dengan dedup HP.
- Pemilih customer jadi `Combobox` dengan pencarian + opsi "Buat customer '…'".

**Tidak termasuk**
- Field email/sumber/catatan customer di form order — cukup nama + HP; lengkapi di menu Customer.
- Mengganti pemilih di POS (tetap input nama + HP dari 2.1).
- Mengedit data customer yang sudah ada dari form order.

## Aturan bisnis

1. Tepat **satu** dari `customer_id` / `new_customer.name` harus terisi; keduanya kosong → 422 di `customer_id` ("Pilih customer atau isi nama customer baru."); keduanya terisi → `customer_id` dipakai, `new_customer` diabaikan (klien tidak mengirim keduanya, tapi server tidak boleh membuat baris liar).
2. Dedup saat membuat: bila `new_customer.phone` terisi dan **HP ternormalisasi** (`Phone::normalise()`, 2.1) sama dengan customer yang ada → pakai customer itu, **tidak** membuat baru, nama lama dipertahankan (yang mengetik mungkin salah eja). Tanpa HP → cocokkan nama case-insensitive seperti POS; tidak cocok → buat baru.
3. Nama di-trim; HP disimpan **apa adanya** (format yang diketik), pencocokan memakai bentuk ternormalisasi — konsisten dengan 2.1 supaya `customers.phone` tidak punya dua konvensi.
4. Pembuatan customer dan order dalam **satu transaksi DB** — gagal validasi item tidak boleh meninggalkan customer yatim.
5. Setelah simpan, flash toast menyebut customer baru: "Order ORD-0042 dibuat untuk Budi (customer baru)."

## Perubahan data

Tidak ada — `customers.phone` sudah `nullable string(30)`.

## Backend

### Route
Tidak ada.

### Request
`StoreOrderRequest` (dan `UpdateOrderRequest` dari 1.2 — rules dibagi lewat trait `Requests/Concerns/ResolvesCustomer` (baru)):

```php
'customer_id'        => ['nullable', 'integer', 'exists:customers,id', 'required_without:new_customer.name'],
'new_customer'       => ['nullable', 'array'],
'new_customer.name'  => ['nullable', 'string', 'max:255', 'required_without:customer_id'],
'new_customer.phone' => ['nullable', 'string', 'max:30'],   // sama dengan CustomerRequest
```

`attributes()`: `new_customer.name` → "nama customer baru", `new_customer.phone` → "no HP customer baru". Pesan `required_without` untuk `customer_id` di-override di `messages()` menjadi kalimat aturan 1.

Trait menyediakan `resolveCustomer(): Customer` — dipanggil **di dalam** transaksi controller, bukan di `after()` validator (validator tidak boleh menulis).

### Controller / Action / Service
- Logika pencocokan dipindah dari `PosController::customerFor()` (private) ke action (baru) `Modules\Customer\Actions\FindOrCreateCustomer::execute(string $name, ?string $phone): Customer` — dipakai POS (2.1) dan form order; satu aturan dedup. `PosController` memanggil action ini (hapus method private-nya).
- `OrderController@store`: `$customer = $request->integer('customer_id') ?: $findOrCreate->execute(...)` di dalam `DB::transaction`, lalu `'customer_id' => $customer->id`.
- `OrderController@create`/`@edit` props `customers` tetap `{id, name, phone}` — Combobox mencari di klien (daftar customer ratusan baris masih ringan; paginasi customer di 3.1 tidak menyentuh prop ini).

## Frontend

- Tambah primitive `components/ui/combobox.tsx` dari registry shadcn base (`npx shadcn add combobox` — belum ada di `components/ui/`; cek `components.json` style `base-maia`).
- `modules/order/components/order-form.tsx` (dari 1.2; bila 1.2 belum merge, lakukan di `create.tsx` dan 1.2 mengekstrak): ganti `Select` customer dengan `Combobox`:
  - Item: `{c.name} · {c.phone}`; pencarian cocok nama atau HP (digit).
  - Bila ketikan tidak cocok persis dengan nama mana pun → item terakhir **"Buat customer '{ketikan}'"**. Memilihnya menetapkan `data.new_customer.name = ketikan`, mengosongkan `customer_id`, dan menampilkan `Input` HP inline di bawah (label "No HP (opsional)", placeholder "08…") + badge "Customer baru".
  - Tombol ✕ pada badge membatalkan → kembali ke pemilih.
- `OrderForm` state: `customer_id: string; new_customer: { name: string; phone: string } | null`. `useForm` mengirim hanya salah satu (`transform` membuang `new_customer` bila `customer_id` terisi).
- Ringkasan kanan menampilkan nama customer baru dengan keterangan "(baru)".
- Error `errors['new_customer.name']` / `errors['new_customer.phone']` ditampilkan di field inline; `errors.customer_id` di bawah Combobox.
