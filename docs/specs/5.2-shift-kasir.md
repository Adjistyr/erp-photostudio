# 5.2 Shift kasir (buka / tutup laci)

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 5 — Saat admin mulai input | P3 | L | 5.1 (peran), 3.3 (`CashReceipts`), 0.1 (`created_by`) | K4 |

## Tujuan

Uang **tunai** yang masuk selama satu shift bisa dicocokkan dengan isi laci saat tutup: saldo awal + tunai masuk − tunai keluar = ekspektasi; selisih dengan hitungan fisik tercatat dan diketahui siapa pemegang shiftnya. Hanya berarti saat ada > 1 pemegang kas — jangan dibangun sebelum 5.1 dipakai.

## Lingkup

**Termasuk**
- Tabel `cash_shifts`, buka/tutup shift, syarat shift terbuka untuk pembayaran tunai, banner di POS, ringkasan shift di Laporan Kas Harian.

**Tidak termasuk**
- Setoran kas ke bank / kas keluar bebas di tengah shift (petty cash) — biaya operasional sudah punya jalurnya; penarikan ke bank dicatat sebagai `note` saat tutup.
- Multi-laci / multi-outlet.
- Shift untuk transfer/QRIS — uang itu tidak ada di laci.
- Mengunci tanggal transaksi ke shift — pembayaran tetap bertanggal `paid_on`; shift hanya untuk tunai yang **dicatat selama shift terbuka** (`payments.cash_shift_id`).

## Aturan bisnis

1. Satu shift terbuka pada satu waktu (seluruh app, bukan per user).
2. Pembayaran **tunai** (POS, catat bayar, dan refund tunai setelah 4.2) membutuhkan shift terbuka → kalau tidak ada: 422 "Buka kasir dulu sebelum menerima tunai." Transfer/QRIS tidak terpengaruh.
3. Pembayaran tunai yang dicatat saat shift terbuka diikat ke shift itu (`payments.cash_shift_id`), apa pun `paid_on`-nya — yang dihitung adalah uang yang **masuk ke laci**, bukan tanggal nota.
4. `expected_cash = opening_cash + Σ payments.amount (cash, shift ini) − Σ refunds.amount (cash, shift ini)`. Dihitung, tidak disimpan sampai tutup; saat tutup nilainya dibekukan ke kolom.
5. `difference = counted_cash − expected_cash`; boleh negatif/positif; selisih ≠ 0 mewajibkan `note`.
6. Shift ditutup oleh siapa saja yang login (owner atau admin lain) — yang penting tercatat `closed_by`. Shift tidak bisa dibuka kembali; koreksi = buka shift baru dengan `opening_cash` yang benar dan catatan.
7. Menghapus pembayaran tunai (`delete-money`, owner) yang terikat shift **tertutup** diizinkan (koreksi salah catat), tetapi `expected_cash` shift lama **tidak** dihitung ulang — angka tutup kasir adalah fakta saat itu; perbedaan muncul di Laporan Kas Harian sebagai catatan "1 pembayaran dihapus setelah tutup".
8. Shift yang lupa ditutup > 24 jam → banner peringatan merah di POS dan Dashboard; tidak ditutup otomatis.

## Perubahan data

Tabel (baru) `cash_shifts`:

| Kolom | Tipe | Catatan |
|---|---|---|
| `id` | bigint | |

| `opened_at` | timestamp | |
| `opening_cash` | bigint | ≥ 0 |
| `closed_by` | FK users nullable | |
| `closed_at` | timestamp nullable | null = terbuka |
| `expected_cash` | bigint nullable | dibekukan saat tutup |
| `counted_cash` | bigint nullable | |
| `difference` | bigint nullable | counted − expected |
| `note` | string nullable | wajib bila difference ≠ 0 |
| `created_at`/`updated_at` | | |

Unique partial index PostgreSQL untuk aturan 1 (Blueprint tidak punya API-nya): `DB::statement('CREATE UNIQUE INDEX cash_shifts_one_open ON cash_shifts ((closed_at IS NULL)) WHERE closed_at IS NULL')`. `down()` drop index lalu tabel. Race dua buka bersamaan → yang kedua gagal di DB (ditangkap jadi 422).

`payments`: tambah `cash_shift_id` FK nullable nullOnDelete (hanya terisi untuk `method = cash`). Setelah 4.2: `refunds.cash_shift_id` sama.

Model (baru) `Modules\Finance\Models\CashShift` (`#[Fillable]` semua kolom di atas; casts timestamp; scope `open()`; `isOpen()`), relasi `payments()`. Ditaruh di Finance karena menyentuh kas, bukan order.

## Backend

### Route

| Method | Path | Name | Handler |
|---|---|---|---|
| POST | `shifts` | `shifts.store` | `Modules\Finance\Controllers\CashShiftController@store` |
| PATCH | `shifts/{shift}/close` | `shifts.close` | `@close` |

Keduanya `auth`, `verified`; **tanpa** gate — admin membuka/menutup shiftnya sendiri.

### Request
- `OpenCashShiftRequest` (baru): `opening_cash` required integer min:0. `withValidator`: tolak bila `CashShift::open()->exists()` ("Masih ada kasir yang terbuka sejak {jam} oleh {nama}").
- `CloseCashShiftRequest`: `counted_cash` required integer min:0; `note` nullable string max:255, `required_if` selisih ≠ 0 (dihitung di `withValidator` dari `expected`).
- `StorePosSaleRequest` & `StorePaymentRequest` (& `StoreRefundRequest` 4.2): aturan tambahan `CashShift::requireOpenFor(PaymentMethod $m)` → melempar validation error key `method` "Buka kasir dulu sebelum menerima tunai." bila `cash` dan tidak ada shift terbuka. Dipasang sebagai Rule object (baru) `Modules\Finance\Rules\OpenCashShift`.

### Controller / Action / Service
- `CashShiftController@store`: buat shift (`opened_by = auth()->id()`), flash toast "Kasir dibuka dengan Rp X", `back()`.
- `@close`: hitung `expected` via service (baru) `Modules\Finance\Services\CashShifts::expected(CashShift): int`, simpan `expected_cash/counted_cash/difference/closed_*`, toast "Kasir ditutup. Selisih Rp 0" / "Selisih −Rp 20.000 — tercatat".
- `PosController@store`, `OrderPaymentController@store`: bila `method = cash`, set `cash_shift_id = CashShift::open()->value('id')`. Satu helper `CashShift::currentIdForCash()`.
- `CashReceipts` (3.3): bagian baru `shifts: [{id, opened_at, closed_at, opened_by_name, closed_by_name, opening_cash, expected_cash, counted_cash, difference, note, deleted_after_close: int}]` untuk bulan terpilih.
- Shared props (`HandleInertiaRequests`): `cash_shift: { id, opened_at, opened_by_name, opening_cash, cash_in, hours_open } | null` — dibaca banner POS & Dashboard; satu query ringan per request (`open()->first()` + sum), diterima karena N user kecil; `// ponytail: hitung per request, cache bila terasa`.

### Props Inertia

```ts
// shared
cash_shift: { id: number; opened_at: string; opened_by_name: string | null; opening_cash: number; cash_in: number; hours_open: number } | null;

```

## Frontend

- Komponen (baru) `components/cash-shift-banner.tsx`: dipakai di `pos.tsx` (atas) dan `dashboard.tsx`. Tiga keadaan: **tertutup** → `Alert` "Kasir belum dibuka" + tombol "Buka kasir" (dialog saldo awal); **terbuka** → "Shift Agung sejak 09:02 · tunai masuk Rp 450.000" + tombol "Tutup kasir"; **> 24 jam** → varian `destructive` "Kasir terbuka sejak kemarin 09:02 — tutup dan buka ulang".
- Dialog tutup: menampilkan Saldo awal, Tunai masuk, Tunai keluar (refund), **Ekspektasi** (mono besar), input "Uang di laci", selisih dihitung langsung (hijau 0 / merah ≠ 0), catatan wajib bila selisih ≠ 0 (pesan inline).
- POS: tombol metode "Tunai" tetap bisa dipilih; saat submit tanpa shift, error server tampil di bawah metode + tautan "Buka kasir" yang membuka dialog — tidak men-disable tombol supaya pengguna tahu kenapa.
- Laporan Kas Harian: bagian "Shift" di bawah tabel per hari; baris selisih ≠ 0 merah; kolom `deleted_after_close` ditampilkan sebagai catatan kecil.
