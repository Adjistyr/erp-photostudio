# 7.1 Galeri foto + profil publik item katalog

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 7 — Permintaan tambahan (9 Okt 2026) | P2 | L | — | Galeri per item **dan** deskripsi + penanda company profile sekarang (user, 9 Okt 2026) |

## Tujuan

Produk di POS dikenali dari fotonya, bukan hanya nama. Katalog sekaligus jadi sumber data company profile nanti: tiap item punya galeri foto, deskripsi, dan penanda apakah boleh tampil ke publik.

## Lingkup

**Termasuk**
- Galeri foto per item katalog (produk **dan** jasa), maksimal 8 foto. Foto pertama = sampul.
- Unggah (beberapa sekaligus), hapus, dan "Jadikan sampul" dari dialog Edit di Katalog.
- Kolom `description` (teks bebas) dan `is_public` ("Tampil di company profile") di item katalog.
- Sampul tampil di grid POS dan kolom Nama daftar Katalog.

**Tidak termasuk**
- Endpoint/halaman publik untuk company profile — company profile adalah produk terpisah (Paket A, `docs/demo-client.md`). Saat dibangun, ia hanya boleh membaca item `is_public && is_active` dengan field nama, kategori, deskripsi, foto (harga diputuskan saat itu). **`unit_cost` tidak pernah keluar.**
- Urut ulang galeri dengan seret — cukup "Jadikan sampul"; urutan sisanya = urutan unggah.
- Foto di form Buat/Ubah Order, struk, dan invoice — order menyimpan snapshot tanpa foto.
- Penyimpanan cloud (S3) — disk `public` lokal; pindah cukup lewat konfigurasi disk saat hosting diputuskan.
- Hak akses (siapa boleh mengubah foto) — ikut 5.1.

## Aturan bisnis

1. Format JPG, PNG, atau WebP. Server **selalu menyandikan ulang** ke WebP: ukuran besar (sisi terpanjang ≤ 1600 px) dan thumbnail persegi 400 × 400 (crop tengah). File asli tidak disimpan — EXIF (termasuk lokasi GPS foto HP) ikut terbuang.
2. Browser mengecilkan foto ke sisi terpanjang ≤ 1600 px sebelum mengunggah. Alasannya batas upload PHP bawaan 2 MB per file, sementara foto HP 3–8 MB. Server tetap memvalidasi: ≤ 2 MB per file, dimensi ≤ 4000 × 4000 (batas memori GD).
3. Maksimal 8 foto per item. Unggahan yang membuat jumlah > 8 ditolak seluruhnya dengan pesan berapa sisa slot.
4. Sampul = foto dengan `position` terkecil. "Jadikan sampul" memindahkan foto itu ke depan; urutan foto lain tetap.
5. Hapus foto menghapus baris dan kedua filenya, lewat konfirmasi. Tidak ada riwayat — foto bukan catatan uang.
6. Foto milik item lain tidak bisa dihapus/dijadikan sampul lewat URL item ini (404).
7. Item nonaktif tetap menyimpan fotonya. Penanda `is_public` tidak membuat item tampil di POS/form order; nonaktif tetap berarti tersembunyi dari keduanya **dan** dari company profile nanti.
8. `description` opsional, maksimal 2000 karakter. `is_public` default `false`.
9. Grid POS: bila **tidak ada** produk aktif yang berfoto, kartu tampil seperti sekarang (teks saja). Bila ada, semua kartu punya area gambar; produk tanpa foto mendapat ikon pengganti — tinggi kartu seragam.

## Backend

### Route (grup `web` + `auth` + `verified`, `scopeBindings`)

| Method | Path | Name | Handler |
|---|---|---|---|
| POST | `catalog/{catalogItem}/photos` | `catalog.photos.store` | `CatalogPhotoController@store` |
| DELETE | `catalog/{catalogItem}/photos/{photo}` | `catalog.photos.destroy` | `CatalogPhotoController@destroy` |
| PATCH | `catalog/{catalogItem}/photos/{photo}/cover` | `catalog.photos.cover` | `CatalogPhotoController@cover` |

### Request
- `CatalogItemRequest`: tambah `description` nullable string max 2000, `is_public` boolean.
- `StoreCatalogPhotosRequest`: `photos` required array min 1; `photos.*` `image`, `mimes:jpg,jpeg,png,webp`, `max:2048`, `dimensions:max_width=4000,max_height=4000`; `after()`: jumlah lama + baru > 8 → error `photos` "Maksimal 8 foto per item — sisa N slot."

### Controller / Action
- `Modules\Catalog\Actions\StoreCatalogPhoto::execute(CatalogItem, UploadedFile)` — GD: decode, skala, crop thumbnail, simpan dua WebP, buat baris dengan `position = max + 1`. Alpha PNG dipertahankan.
- `CatalogPhotoController@store` loop dalam transaksi DB; bila satu foto gagal, file yang sudah tertulis dihapus. `destroy` hapus file + baris. `cover` set `position` foto = (min − 1). Semua `back()` + toast.
- `CatalogItemController@store` flash `catalog_created` (id) supaya dialog langsung pindah ke mode Edit untuk menambah foto.

### Props Inertia
- `catalog::index` `items[]` + `description: string | null`, `is_public: boolean`, `photos: { id, url, thumb_url }[]` (urut sampul dulu).
- `pos.index` `products[]` + `photo_url: string | null` (thumbnail sampul).

## Frontend

- `lib/photo-resize.ts`: `fitWithin(w, h, max)` (murni) + `resizeForUpload(file)` (canvas → JPEG kualitas 0,85; file yang sudah kecil dikirim apa adanya).
- Dialog item Katalog: field Deskripsi (`Textarea`) dan checkbox "Tampil di company profile" ikut tombol Simpan. Bagian **Foto** hanya di mode Edit: grid thumbnail, tombol "Tambah foto" (`<input type="file" multiple accept>`), per foto: Jadikan sampul, Hapus (AlertDialog). Catatan: "Foto tersimpan langsung, tidak menunggu Simpan." Mode Tambah menampilkan "Foto bisa ditambahkan setelah item disimpan" — setelah simpan dialog pindah ke Edit item itu.
- Daftar Katalog: thumbnail 40 px di kolom Nama (ikon pengganti bila kosong), badge "Profil" bila `is_public`.
- POS: aturan 9.
