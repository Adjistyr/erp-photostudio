# 4.1 Diskon persen di POS

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 4 — Kenyamanan transaksi | P2 | S | — | — |

## Tujuan

Admin bisa mengetik "10%" alih-alih menghitung Rp 8.000 di kepala. Nominal tetap yang disimpan — laporan dan invoice tidak berubah.

## Lingkup

**Termasuk**
- Toggle `Rp | %` di field diskon POS; mode % dikonversi ke nominal di klien sebelum dikirim.
- Keterangan konversi ("10% = Rp 8.000") dan pembulatan yang pasti.

**Tidak termasuk**
- Diskon **per item** — butuh kolom di `order_items`, mengubah Laporan Penjualan per produk; nilai tambah kecil di volume ini.
- Diskon persen di form Buat Order (studio/event) — harga paket adalah hasil nego, biasanya sudah angka bulat; tambah kalau diminta.
- Menyimpan "asal diskon" (persen vs nominal) di DB — tidak ada yang membacanya.

## Aturan bisnis

1. Yang dikirim ke server tetap `discount` nominal (integer rupiah); server **tidak tahu** ada mode persen → tidak ada perubahan backend, aturan "diskon < subtotal" di `StorePosSaleRequest::after()` tetap berlaku.
2. Konversi: `nominal = Math.round(subtotal × persen / 100)`; persen 0–99,99, dua desimal maksimum (input `step="0.01"`).
3. Saat subtotal berubah (item ditambah/dikurangi) dalam mode %, nominal **dihitung ulang** — persen yang dipertahankan, bukan rupiahnya. Dalam mode Rp, nominal tetap.
4. Pindah mode mengonversi nilai yang ada ke representasi lain (`Rp 8.000` → `10%` jika subtotal 80.000; hasil persen dibulatkan dua desimal). Pindah mode tidak mengosongkan field.
5. Persen ≥ 100 → ditolak di klien dengan pesan "Diskon harus di bawah 100%"; tombol simpan nonaktif (konsisten dengan aturan server).

## Frontend

- `resources/js/modules/order/lib/discount.ts` (baru):
  ```ts
  export type DiscountMode = 'rp' | 'pct';
  /** Persen → rupiah, dibulatkan ke rupiah terdekat. */
  export function persenKeNominal(subtotal: number, persen: number): number;
  /** Rupiah → persen dua desimal; subtotal 0 → 0. */
  export function nominalKePersen(subtotal: number, nominal: number): number;
  ```
- `resources/js/modules/order/pages/pos.tsx`: state lokal `discountMode` (default `'rp'`) dan `discountInput: string` (teks yang diketik). `form.data.discount` (yang dikirim) diturunkan: mode `rp` → `Number(discountInput)`, mode `pct` → `persenKeNominal(subtotal, Number(discountInput))`. Sudah ada `const discount = Math.min(Number(data.discount) || 0, subtotal)` — ganti sumbernya ke turunan ini; `setData('discount', …)` dipanggil di `useEffect` saat `discountInput`/`discountMode`/`subtotal` berubah (aturan 3).
- UI: `ToggleGroup` kecil (`Rp` / `%`) di kanan label "Diskon", memakai komponen yang sama dengan pemilih metode bayar. Di bawah input, teks `text-xs text-muted-foreground`: mode `pct` → "10% = Rp 8.000"; mode `rp` → "= 10% dari subtotal" (hanya bila subtotal > 0).
- Pesan error klien untuk persen ≥ 100 ditampilkan lewat `InputError` yang sudah ada; `errors.discount` dari server tetap ditampilkan di tempat yang sama.
