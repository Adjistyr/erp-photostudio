# 1.1 Kategori jasa terstruktur

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 1 — Data order yang bisa dikoreksi | P1 | S | — | K2 (kategori tak dikenal dibiarkan + peringatan) |

## Tujuan

Form Buat Order memfilter paket dengan perbandingan string persis `Studio` / `Event` / `Add-on` (`create.tsx` `categoryMatches()`), sementara Katalog menerima kategori teks bebas (`CatalogItemRequest`: `nullable|string|max:100`, kosong → "Lain-lain"). Jasa berkategori "studio" atau "Lain-lain" **tidak pernah muncul** di Buat Order dan tidak ada yang memberi tahu. Spek ini mengunci kategori jasa ke tiga nilai dan menampilkan jasa yang tersesat.

## Lingkup

**Termasuk**
- Enum `ServiceCategory` (baru) + validasi kategori jasa di request.
- Migrasi data yang menormalkan huruf/spasi saja (K2).
- Penanda "kategori tidak dikenal" di Katalog; filter Buat Order memakai enum.

**Tidak termasuk**
- Kategori **produk** — tetap teks bebas; tidak ada layar yang bergantung pada nilainya.
- Pemetaan otomatis kategori asing (mis. "Wedding" → "Event") — K2.
- Pencarian/urut katalog (3.6), bundel (6.3).

## Aturan bisnis

1. Jasa (`type = service`) hanya boleh berkategori `Studio`, `Event`, atau `Add-on` — tepat huruf besar/kecil seperti itu, karena nilai inilah yang sudah tersimpan di data dan dibaca `create.tsx`.
2. Produk (`type = product`) tetap kategori bebas, kosong → "Lain-lain" (perilaku lama tidak berubah).
3. Jasa yang kategorinya di luar tiga nilai (data lama) tidak dihapus/diubah otomatis; ditandai `unknown_category` di Katalog dan **tidak dikirim** ke Buat Order (sama seperti sekarang — bedanya sekarang terlihat).
4. Mengubah jasa yang kategorinya tidak dikenal **wajib** memilih salah satu dari tiga — form tidak bisa disimpan dengan kategori lama.
5. `Add-on` muncul di order studio maupun event; `Studio` hanya studio; `Event` hanya event (aturan `categoryMatches()` yang ada, tidak berubah).

## Perubahan data

Enum `Modules\Catalog\Enums\ServiceCategory: string` (baru):

```php
enum ServiceCategory: string
{
    case Studio = 'Studio';
    case Event = 'Event';
    case AddOn = 'Add-on';

    /** @return list<string> */
    public static function values(): array { return array_column(self::cases(), 'value'); }

    public function label(): string
    {
        return match ($this) {
            self::Studio => 'Studio — muncul di order sesi studio',
            self::Event => 'Event — muncul di order event',
            self::AddOn => 'Add-on — muncul di keduanya',
        };
    }
}
```

Nilai memakai label berbahasa Indonesia/kapital karena **data yang ada sudah begitu** dan kolom `category` dipakai bersama produk (teks bebas) — tidak diubah ke snake_case supaya migrasi hanya normalisasi, bukan pemetaan.

Migrasi data `2026_10_xx_000003_normalise_service_categories.php` (hanya `up()`; `down()` kosong — normalisasi huruf tidak perlu dibalik):

```php
DB::statement(<<<'SQL'
    UPDATE catalog_items
    SET category = CASE lower(trim(category))
        WHEN 'studio' THEN 'Studio'
        WHEN 'event' THEN 'Event'
        WHEN 'add-on' THEN 'Add-on'
        WHEN 'addon' THEN 'Add-on'
        WHEN 'add on' THEN 'Add-on'
    END
    WHERE type = 'service'
      AND lower(trim(category)) IN ('studio', 'event', 'add-on', 'addon', 'add on')
SQL);
```

Tidak ada perubahan skema/kolom. Model `CatalogItem` menambah helper:

```php
public function hasKnownServiceCategory(): bool
{
    return $this->type !== CatalogItemType::Service
        || ServiceCategory::tryFrom($this->category) !== null;
}
```

## Backend

### Route
Tidak ada.

### Request

`Modules/Catalog/Requests/CatalogItemRequest.php`:

```php
$isProduct = $this->input('type') === CatalogItemType::Product->value;
// ...
'category' => $isProduct
    ? ['nullable', 'string', 'max:100']
    : ['required', Rule::in(ServiceCategory::values())],
```

Pesan: `messages()` → `'category.in' => 'Kategori jasa harus Studio, Event, atau Add-on — menentukan di mana paket muncul saat Buat Order.'`, `'category.required'` sama. `catalogData()` tidak berubah (jasa selalu terisi; produk kosong → "Lain-lain").

### Controller / Action / Service

- `CatalogItemController@index`: `get([...])` → tambah `unknown_category` per item. Karena `get()` dengan kolom tertentu, pakai `->map(fn (CatalogItem $i) => [...$i->toArray(), 'unknown_category' => ! $i->hasKnownServiceCategory()])` — atau ubah ke `->get()` lalu map manual field yang dikirim (lebih eksplisit, pilih ini). Props menambah `service_categories: [{value, label}]` untuk Select.
- `OrderController@create`: query katalog menambah `->whereIn('category', ServiceCategory::values())`. Hasil sama dengan sekarang untuk data benar; untuk data salah, aturannya sekarang ada di server, bukan tersembunyi di klien.

### Props Inertia

```ts
// catalog::index
items: { ...CatalogItem; unknown_category: boolean }[];
service_categories: { value: ServiceCategory; label: string }[];

// order::create — tidak berubah bentuk; catalog[].category sekarang dijamin ServiceCategory
```

## Frontend

- `resources/js/types/domain.ts`: `export type ServiceCategory = 'Studio' | 'Event' | 'Add-on'` + `SERVICE_CATEGORIES` list. Letaknya di `types/domain` (bukan `modules/catalog/types`) karena dipakai dua modul (Catalog, Order).
- `resources/js/modules/catalog/pages/index.tsx` `ItemDialog`: field kategori dirender kondisional — `data.type === 'service'` → `Select` (`items={service_categories}` — ingat gotcha #10 `SelectValue` butuh `items` agar label tampil) dengan `FieldDescription` "Menentukan di mana paket muncul saat Buat Order"; `product` → `Input` seperti sekarang. Saat toggle jenis berubah, reset `category` ke `''` supaya nilai teks bebas tidak terbawa ke jasa. `complete` menambah syarat: jasa wajib `category !== ''`.
- Tabel katalog: baris jasa dengan `unknown_category` → `Badge variant="destructive"` "Kategori tidak dikenal" dengan `title`/tooltip "Tidak muncul di Buat Order — ubah kategorinya"; tombol Ubah yang ada sudah cukup sebagai jalan keluar. Bila ada ≥ 1 jasa seperti itu, `Alert` di atas tabel: "{n} jasa tidak muncul di Buat Order karena kategorinya tidak dikenal."
- `resources/js/modules/order/pages/create.tsx` `categoryMatches()`: ganti literal dengan konstanta dari `@/types/domain`; tipe `CatalogOption.category` → `ServiceCategory`. Perilaku sama.
