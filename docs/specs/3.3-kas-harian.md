# 3.3 Kas harian per metode

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 3 — Skala & jalan pintas harian | P2 | M | — | K3 (refund mengurangi per metode — dipasang di 4.2) |

## Tujuan

Tiap tutup hari owner mencocokkan **laci kas** dengan penjualan tunai dan **mutasi rekening** dengan transfer/QRIS. Hari ini tidak ada layar yang menjawab "hari Selasa masuk tunai berapa, transfer berapa": Laporan Penjualan per bulan per item, Laporan Laba Rugi per bulan per lini. Data sudah lengkap di `payments` (`paid_on`, `amount`, `method`) — tinggal dikelompokkan.

## Lingkup

**Termasuk**
- Laporan kelima "Kas Harian" di `ReportNav`: per hari × metode untuk satu bulan (`?month=`).
- Service (baru) `Modules\Finance\Services\CashReceipts::forMonth(string $month)`.
- Baris hari ini disorot; total per metode; porsi per metode.

**Tidak termasuk**
- Ekspor CSV — 4.5 memakai `CashReceipts` yang sama.
- Pengurangan refund — 4.2 menambahkannya ke `CashReceipts` (bentuk `days[]` sudah menyediakan tempatnya, lihat Props).
- Shift kasir / saldo awal laci — tidak dikerjakan (POS tanpa shift, keputusan 9 Okt 2026).
- Pengeluaran kas (biaya operasional, biaya job) — laporan ini **penerimaan** saja; pengeluaran sudah ada di Biaya per bulan.

## Aturan bisnis

1. Satu baris = satu tanggal `paid_on` yang punya minimal satu pembayaran; hari tanpa transaksi **tidak** ditampilkan (tabel 31 baris dengan 20 baris nol menyulitkan pencocokan).
2. Kolom per metode = `PaymentMethod` (`cash`, `transfer`, `qris`); jumlah = `SUM(amount)` per hari per metode; `count` = jumlah baris pembayaran hari itu (bukan jumlah order).
3. Total bulan per metode dan total keseluruhan **harus sama** dengan `ProfitAndLoss::revenue($month)` — keduanya membaca `payments.paid_on` dalam `[Periods::start, Periods::end]`. Diuji.
4. Pembayaran order **batal** tetap dihitung — uangnya memang masuk (DP hangus), konsisten dengan Laba Rugi.
5. Bulan tidak valid → `Periods::orCurrent()` (bulan berjalan), sama dengan laporan lain.
6. Setelah 4.2: `days[].refunds` per metode (negatif) dan `net` = penerimaan − refund. Sampai 4.2, kedua kolom itu **tidak dikirim** (bukan nol), supaya UI 3.3 tidak menampilkan kolom kosong.

### Controller / Action / Service

**`Modules\Finance\Services\CashReceipts` (baru)**

```php
final class CashReceipts
{
    /** @return CashReceiptsMonth */
    public function forMonth(string $month): CashReceiptsMonth
    {
        $rows = Payment::query()
            ->selectRaw('paid_on, method, SUM(amount) AS amount, COUNT(*) AS count')
            ->whereBetween('paid_on', [Periods::start($month), Periods::end($month)])
            ->groupBy('paid_on', 'method')
            ->orderBy('paid_on')
            ->get();
        // pivot ke per hari: [date => [cash, transfer, qris, total, count]]
    }
}
```

Agregasi di SQL, bukan memuat semua `Payment` — ini laporan yang akan dibuka tiap hari dan tabel `payments` tumbuh paling cepat.

DTO (baru, di `Modules/Finance/Services/` mengikuti `AgingBucket`, `LineMargin` yang sudah ada di sana):

```php
final readonly class CashDay { public function __construct(public string $date, public array $byMethod /* method => int */, public int $total, public int $count) {} }
final readonly class CashReceiptsMonth { public function __construct(public string $month, public array $days /* list<CashDay> */, public array $totals /* method => int */, public int $total, public int $count) {} }
```

**`ReportController@cash(Request $request, CashReceipts $cash): Response`** — render `finance::reports/cash` dengan props di bawah. Tambahkan `'cash'` ke daftar laporan di komentar kelas (sekarang menyebut empat laporan).

### Props Inertia

```ts
interface Props {
    month: string;                       // 'YYYY-MM'
    today: string;                       // 'YYYY-MM-DD' untuk menyorot baris
    methods: PaymentMethod[];            // urutan kolom: ['cash', 'transfer', 'qris']
    days: {
        date: string;
        by_method: Record<PaymentMethod, number>;
        total: number;
        count: number;
        // 4.2 menambah: refunds: Record<PaymentMethod, number>; net: number;
    }[];
    totals: Record<PaymentMethod, number>;
    total: number;
    count: number;
    shares: Record<PaymentMethod, number>; // 0..1; semua 0 bila total 0
}
```

`methods` dikirim dari server (`PaymentMethod::cases()`) supaya urutan kolom dan enum satu sumber; label dari `PAYMENT_METHOD_LABEL` (`modules/order/types.ts`, diekspor lewat `modules/order/index.ts`).
