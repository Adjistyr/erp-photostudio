# 2.4 Tagih via WA dari layar Pembayaran

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 2 — Bukti ke customer | P2 | S | 2.3 (`customer_phone`, `invoice_url` di props piutang) | K5 — pesan tagihan jadi template `billing` |

## Tujuan

Menagih adalah pekerjaan harian, tapi layar Pembayaran tidak punya tombol WA — yang ada di Invoice → Lihat → Buka WhatsApp, dua layar jauhnya. Semua bahan sudah ada (`whatsappMessage()`, `keNomorWa()`, HP customer). Sekalian memindahkan teks tagihan yang hari ini hard-coded di `invoice-document.tsx` ke template yang bisa diubah owner (K5), supaya Invoice dan Pembayaran memakai **satu** teks.

## Lingkup

**Termasuk**
- Template `billing` di `MessageTemplate::defaults()`; muncul otomatis di Komunikasi.
- `MessageTemplate::fill()` (server) dan `personalise()` (klien, `lib/format.ts`) untuk placeholder bebas.
- Tombol WA per baris di Pembayaran.
- `whatsappMessage()` di Invoice beralih ke template `billing`.

**Tidak termasuk**
- Pengiriman otomatis / WA API — tetap manual (keputusan business-flow).
- Catatan "sudah ditagih tanggal …" per order — berguna, tapi butuh kolom & UI sendiri; ajukan terpisah kalau owner sering lupa siapa yang sudah ditagih.
- Template untuk struk retail / bukti bayar (2.2, 2.3) — teks tetap; K5 hanya untuk pesan **tagihan**.

## Aturan bisnis

1. Pesan tagihan untuk order dengan `balance > 0` selalu berasal dari template `billing` (editan owner kalau ada, default kalau tidak) — di Pembayaran maupun Invoice.
2. Placeholder yang didukung template `billing`: `{nama}` (nama depan customer; "Kak" bila walk-in), `{nomor}` (nomor order `ORD-…`), `{sisa}` (`Rp 1.200.000`), `{jatuh_tempo}` (`12 Okt 2026`), `{link}` (URL invoice signed). Nama studio dan rekening **ditanam** ke teks default lewat `config('studio')` seperti template lain — bukan placeholder.
3. Placeholder yang tidak dikenal dibiarkan apa adanya (tidak error, tidak dihapus) — owner melihat kesalahannya di pratinjau.
4. Order lunas (`balance = 0`) di Invoice memakai teks tetap "Lunas, terima kasih!" (perilaku sekarang), bukan template `billing`.
5. Tanpa HP → tombol disabled dengan tooltip "Belum ada nomor HP"; tidak ada fallback ke email.
6. Baris lewat jatuh tempo (`days_until_due < 0`) → tombol WA bergaya `destructive` outline supaya terlihat prioritas; isi pesan sama (template tidak bercabang; owner bisa menulis kalimat yang berlaku untuk keduanya).

## Perubahan data

Tidak ada migrasi: `message_templates` sudah key–body; baris `billing` hanya tercipta saat owner mengedit (pola yang ada).

`Modules/Customer/Models/MessageTemplate.php`
- `defaults()` tambah:
  ```php
  'billing' => [
      'title' => 'Tagihan',
      'when' => 'Dipakai tombol WA di layar Pembayaran dan "Buka WhatsApp" di Invoice untuk order yang belum lunas.',
      'body' => "Halo {nama}, berikut tagihan {nomor} dari {$studio}. Sisa {sisa}, jatuh tempo {jatuh_tempo}. Pembayaran ke {$bank}. Rincian: {link}",
  ],
  ```
  dengan `$bank = (string) config('studio.bank_account')`.
- Metode baru `public static function fill(string $body, array $values): string` — `str_replace` untuk tiap `{key}` di `$values`; `personalise($body, $name, $link)` **tetap ada** (dipakai `sendEmail`) dan menjadi pembungkus `fill($body, ['nama' => firstName, 'link' => $link])`. Docblock kelas diperbarui: daftar placeholder per template.
- `UpdateMessageTemplateRequest`/`CommunicationController@updateTemplate`: `$key` sudah dicek terhadap `defaults()`? Verifikasi (baris 45–50 memanggil `defaults()[$key]` — kalau key asing akan error 500); bila belum, tambah `abort_unless(array_key_exists($key, MessageTemplate::defaults()), 404)`. Catat sebagai perbaikan sampingan di PR.

## Frontend

### `resources/js/lib/format.ts` (baru)
```ts
/** Ganti {key} → values[key]; placeholder tak dikenal dibiarkan. Sama dengan MessageTemplate::fill. */
export function personalise(template: string, values: Record<string, string>): string
```
Implementasi: `template.replace(/\{(\w+)\}/g, (m, k) => values[k] ?? m)`.
- `communication.tsx`: fungsi lokal `personalise(body, name, link)` (baris 63–70) **dihapus**, diganti impor dari `lib/format` dengan `{ nama: namaDepan(name), link }`. Tambah helper `namaDepan(name: string): string` di `format.ts` (`name.trim().split(' ')[0] || 'Kak'`) — logika yang sama sekarang tersebar di `communication.tsx` dan `whatsappMessage()`.
- Pratinjau template di Komunikasi memakai nilai contoh untuk placeholder baru: `{ nama: sampleName, link: '[link]', nomor: 'ORD-0012', sisa: 'Rp 1.200.000', jatuh_tempo: '12 Okt 2026' }`; teks bantuan placeholder (baris ±388, ±589) menambah daftar untuk template `billing`.

### `invoice-document.tsx`
- `whatsappMessage(invoice, studio, billingTemplate: string)`: bila `invoice.balance > 0` → `personalise(billingTemplate, { nama, nomor: invoice.order_number, sisa: formatRp(balance), jatuh_tempo: formatTanggal(service_date), link: public_url })`; bila lunas → teks tetap seperti sekarang (cabang lunas dipertahankan). Pemanggil di `invoices.tsx` meneruskan `billing_template`.

### `receivables.tsx`
- Props `+ billing_template`. Kolom aksi: sebelum *Catat Bayar*, `Button size="icon-sm" variant="outline"` + `className={o.days_until_due < 0 ? 'border-destructive text-destructive' : ''}` (varian `button.tsx` yang ada: default/outline/secondary/ghost/destructive/link — tidak ada destructive-outline; jangan tambah varian baru untuk satu tombol), ikon `MessageCircle`/`Send` (lucide — `Send` sudah dipakai di `invoices.tsx`), `aria-label="Tagih via WhatsApp"`.
- Aktif: `<a href={`https://wa.me/${keNomorWa(o.customer_phone)}?text=${encodeURIComponent(personalise(billing_template, {...}))}`} target="_blank" rel="noreferrer">` via `render=`/`nativeButton={false}`. Tanpa HP: `disabled` + `Tooltip` (`components/ui/tooltip.tsx`, sudah ada) "Belum ada nomor HP".
- Caption kecil di bawah tabel: "Pesan tagihan diambil dari template *Tagihan* di Komunikasi." dengan `Link` ke `communication.index`.
