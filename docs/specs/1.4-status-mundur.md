# 1.4 Status mundur satu langkah

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 1 — Data order yang bisa dikoreksi | P2 | S | 0.2 `order_events` | — |

## Tujuan

Status kerja hanya maju (`WorkStatus::next()`; komentar di enum: "tidak ada mundur"). Salah klik "Lanjut ke Selesai Dikerjakan" permanen — satu-satunya jalan adalah membatalkan order. Dengan riwayat (0.2) alasan menolak mundur ("perlu mendesain alur pembatalan status") sudah hilang: mundur satu langkah, tercatat siapa dan kapan.

## Lingkup

**Termasuk**
- `WorkStatus::previous()`, route `orders.revert`, event `reverted`, tombol "Kembalikan ke …" di Sheet detail.

**Tidak termasuk**
- Mundur dari **Batal** — pembatalan tetap final; order yang terlanjur dibatalkan dibuat ulang (dan dengan 4.2, DP-nya bisa direfund atau dipindah secara eksplisit).
- Lompat lebih dari satu langkah — klik dua kali.
- Menghapus `result_link` saat mundur dari Selesai/Diserahkan — link tetap tersimpan, hanya disembunyikan oleh `allowsResultLink()` yang ada.
- Mundur mengubah pembayaran — tidak ada hubungan; status bayar turunan.

## Aturan bisnis

1. `previous()` adalah kebalikan persis `next()`: Scheduled→Booking, InProgress→Scheduled, Done→InProgress, Delivered→Done. `Booking` dan `Cancelled` → `null`.
2. Mundur hanya satu langkah per permintaan; server yang menentukan tujuannya (klien mengirim "kembalikan", bukan status) — simetris dengan `advance`.
3. Order Batal → 422 "Order yang dibatalkan tidak bisa dikembalikan statusnya." Booking → 422 "Booking adalah status awal."
4. Mundur dari Dijadwalkan ke Booking **boleh walau ada DP** — Booking+DP memang tidak lahir dari `store()` (DP → Dijadwalkan), tetapi melarangnya berarti owner yang salah klik dua kali tidak bisa kembali. Konsekuensi: badge progres Booking dengan badge bayar DP; tidak ada rumus yang bergantung pada kombinasi ini (status bayar turunan).
5. `result_link` tidak dihapus (lihat Tidak termasuk).
6. Satu event `reverted` `{work_status: {from, to}}` dalam transaksi yang sama.

## Perubahan data

Tidak ada migrasi.

`Modules/Order/Enums/WorkStatus.php`:

```php
/** Kebalikan next() — koreksi salah klik, satu langkah, tercatat di order_events (1.4). */
public function previous(): ?self
{
    return match ($this) {
        self::Scheduled => self::Booking,
        self::InProgress => self::Scheduled,
        self::Done => self::InProgress,
        self::Delivered => self::Done,
        self::Booking, self::Cancelled => null,
    };
}
```

Perbarui komentar `next()` yang menyatakan "tidak ada mundur" (jangan hapus kalimatnya — ubah menjadi: dulu tidak ada mundur karena belum ada riwayat; sejak 1.4 ada `previous()` yang tercatat).

## Backend

### Route

`Modules/Order/Routes/web.php`, setelah `orders.advance`:

```php
Route::patch('orders/{order}/revert', [OrderController::class, 'revert'])->name('orders.revert');
```

### Request
Tidak ada body — pola sama `advance(Order $order)`.

### Controller / Action / Service

`OrderController@revert(Order $order, RecordOrderEvent $events)`:

```php
$previous = $order->work_status->previous();
if ($previous === null) {
    throw ValidationException::withMessages(['work_status' => $order->isCancelled()
        ? 'Order yang dibatalkan tidak bisa dikembalikan statusnya.'
        : 'Booking adalah status awal.']);
}

DB::transaction(function () use ($order, $previous, $events) {
    $from = $order->work_status;
    $order->update(['work_status' => $previous]);
    $events->execute($order, 'reverted', ['work_status' => ['from' => $from->value, 'to' => $previous->value]]);
});

Inertia::flash('toast', ['type' => 'success', 'message' => "{$order->number}: status kembali ke {$previous->label()}."]);
return to_route('orders.index');
```

`advance()` dibungkus transaksi di 0.2 — pastikan bentuknya sama.

### Props Inertia

`orderProps()` menambah:

```ts
previous_status: WorkStatus | null;   // null = Booking atau Batal
```

- `resources/js/modules/order/pages/index.tsx` `StatusControl`: di bawah/samping tombol "Lanjut ke {label}" tambah tautan kecil (`Button variant="ghost" size="sm"`, `text-muted-foreground`) "Kembalikan ke {WORK_STATUS_LABEL[previous_status]}" — hanya bila `previous_status !== null`. Klik → `AlertDialog` (pola `CancelOrder`): judul "Kembalikan status {number}?", isi "Status kembali ke {label}. Tercatat di riwayat order; pembayaran dan link hasil tidak berubah." Tombol konfirmasi "Kembalikan" → `router.patch(OrderController.revert(order.id).url, {}, {preserveScroll: true})`.
- Dari Diserahkan: tombol "Lanjut ke" tidak ada (`next_status` null) — hanya "Kembalikan ke Selesai Dikerjakan". Dari Booking: hanya "Lanjut ke Dijadwalkan".
- Riwayat (0.2) sudah merender `reverted` lewat `describeEvent()` → "Status Diserahkan → Selesai Dikerjakan" dengan label tipe "Status dikembalikan".
