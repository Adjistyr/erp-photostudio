# 3.6 Katalog & Aset: penanda margin rendah + pencarian klien

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 3 — Skala & jalan pintas harian | P3 | S | 3.1 (`list-toolbar.tsx` mode klien) | — |

## Tujuan

**Koreksi terhadap rencana:** Katalog **sudah** menampilkan kolom HPP, Margin (Rp), dan Margin % per produk (`modules/catalog/pages/index.tsx`, dihitung di klien dari `price` dan `unit_cost`). Yang belum ada: (1) produk bermargin tipis tidak menonjol di antara baris lain, (2) tidak ada pencarian nama di Katalog maupun Aset — keduanya masih < 50 baris, jadi filter klien cukup, tapi mengetik lebih cepat daripada memindai saat katalog tumbuh ke puluhan item cetak.

## Lingkup

**Termasuk**
- Ambang margin rendah di `config/studio.php` → `low_margin_ratio` (default `0.2`), dikirim sebagai prop; sel Margin % produk di bawah ambang diberi warna `text-destructive` + tooltip di header yang menjelaskan ambang.
- Input cari klien (`ListToolbar` mode klien) di Katalog (nama, kategori) dan Aset (kode, nama, model, kategori), digabung dengan tab yang sudah ada.

**Tidak termasuk**
- Menghitung margin di server — perhitungan klien yang ada sudah benar dan satu sumber (`price − unit_cost`), tidak perlu dipindah.
- Paginasi / pencarian server — kalau katalog/aset melewati ~200 baris, pindah ke pola 3.1.
- Pengurutan berdasarkan margin — tab + cari cukup; urutan tetap produk dulu lalu id (komentar di controller).
- Margin jasa — HPP jasa tidak tetap (dicatat per job), sel tetap `—` (`NotApplicable`).

## Aturan bisnis

1. Produk dianggap **margin rendah** bila `(price − unit_cost) / price < low_margin_ratio`. Produk dengan `price` 0 tidak mungkin (request `min:1`).
2. Ambang satu angka untuk seluruh katalog, dari konfigurasi (`STUDIO_LOW_MARGIN_RATIO` di `.env`, default 0.2), **bukan** diinput per item — owner belum minta ambang per kategori; kalau minta, jadi kolom.
3. Pencarian Katalog cocok tanpa membedakan huruf besar pada `name` dan `category`; Aset pada `code`, `name`, `model`, `category`. Digabung AND dengan tab aktif (Katalog: Semua/Produk/Jasa; Aset: tab yang ada bila ada).
4. Baris nonaktif (Katalog) dan dilepas (Aset) tetap ikut dicari — admin mencari "kenapa item ini tidak muncul di POS" dan jawabannya adalah badge Nonaktif.
5. Penanda margin rendah muncul juga untuk item **nonaktif** (konsisten: kolom lain pun tampil).

## Frontend

**`modules/catalog/pages/index.tsx`**
- `ListToolbar` mode klien (`value={{ q }}`, tanpa `filters` — tab jenis tetap `Tabs`), placeholder "Cari nama atau kategori…"; `visible = items.filter(tab).filter(q)` lewat fungsi murni `filterCatalog(items, { type, q })` di `modules/catalog/lib/filter.ts` (baru).
- Header `Margin %` dibungkus `Tooltip`: "Merah bila di bawah {formatPersen(low_margin_ratio)} — ambang di konfigurasi studio." Sel Margin % produk: `className={ratio < low_margin_ratio ? 'text-destructive' : ''}` + `title` yang sama (untuk pembaca layar/hover tanpa tooltip header).
- `KosongTabel`: saat `q` terisi dan hasil kosong → "Tidak ada item yang cocok." + aksi "Hapus pencarian"; saat katalog kosong → kalimat lama + aksi tambah.

**`modules/asset/pages/index.tsx`**
- `ListToolbar` mode klien di atas tabel; `filterAssets(assets, { q })` di `modules/asset/lib/filter.ts` (baru); `KosongTabel` dua varian seperti Katalog.
