# 1.3 Item custom di Buat/Edit Order

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 1 — Data order yang bisa dikoreksi | P1 | M | 1.2 (form bersama `order-form.tsx`, `UpdateOrderRequest`) | — |

## Tujuan

Paket event hampir selalu hasil nego; hari ini item **wajib** dari katalog dengan harga katalog (`StoreOrderRequest`: `items.*.catalog_item_id` `required`). Kolom `order_items.catalog_item_id` sudah `nullable` dengan komentar "Null untuk item custom event yang tidak diambil dari katalog" — skema siap, request dan form belum. Spek ini membuka item custom (nama + harga bebas) untuk order studio/event.

## Lingkup

**Termasuk**
- `StoreOrderRequest` dan `UpdateOrderRequest` menerima baris tanpa `catalog_item_id` (nama + harga).
- Trait `ResolvesCatalogLines` menghasilkan baris custom.
- Baris "Item custom" di Laporan Penjualan bagian jasa.
- Badge "Custom" di Sheet detail, form, dan invoice.

**Tidak termasuk**
- Item custom di **POS** — retail = katalog (produk fisik dengan HPP); tanpa HPP margin retail bohong.
- HPP untuk item custom — `unit_cost` null; biaya nyatanya dicatat sebagai biaya job (sama seperti jasa katalog).
- Menyimpan item custom ke katalog ("simpan sebagai paket") — kalau sering dipakai, owner menambahkannya di Katalog.
- Diskon per item — harga custom sudah menampung harga deal.

## Aturan bisnis

1. Baris item **salah satu**: `catalog_item_id` terisi (baris katalog) **atau** `name` + `unit_price` terisi (baris custom). Baris katalog: `name`/`unit_price` dari klien **diabaikan** — server menyalin dari katalog (mencegah harga katalog dimanipulasi dari klien).
2. Baris custom: `name` 1–255 karakter, `unit_price` integer ≥ 0 (0 diizinkan untuk "bonus" yang ingin tercetak di invoice), `quantity` 1–999, `unit_cost` = null, `catalog_item_id` = null.
3. Hanya order lini studio & event (sama dengan form order). POS tetap menolak baris tanpa `catalog_item_id`.
4. Harga custom adalah snapshot sejak awal (tidak ada sumber lain) — edit order (1.2) memperlakukan baris custom lama seperti baris katalog lama: hanya `quantity` yang boleh berubah; ubah nama/harga = hapus + tambah. Mengubah nama/harga pada baris lama → 422 "Ubah item custom dengan menghapus baris lalu menambah yang baru."
5. `Order::total()`, `margin()`, `materialCost()` (unit_cost null → 0) sudah benar tanpa perubahan.
6. Laporan Penjualan: item custom tidak masuk "jasa terlaris" per paket (tidak ada paket), tapi **nilainya tidak boleh hilang** — satu baris agregat "Item custom (n order)" di bawah daftar jasa.

## Perubahan data

Tidak ada migrasi (`catalog_item_id` sudah nullable, `unit_cost` sudah nullable).

## Backend

### Route
Tidak ada.

### Request

`StoreOrderRequest` dan `UpdateOrderRequest` — rules `items.*` menjadi:

```php
'items.*.catalog_item_id' => ['nullable', 'integer', Rule::exists('catalog_items', 'id')
    ->where('is_active', true)->where('type', CatalogItemType::Service->value)],
'items.*.name' => ['required_without:items.*.catalog_item_id', 'nullable', 'string', 'max:255'],
'items.*.unit_price' => ['required_without:items.*.catalog_item_id', 'nullable', 'integer', 'min:0'],
'items.*.quantity' => ['required', 'integer', 'min:1', 'max:999'],
```

Di `UpdateOrderRequest`, `exists` tanpa `is_active` (lihat 1.2). `attributes()`: `'items.*.name' => 'nama item'`, `'items.*.unit_price' => 'harga item'`. Pesan `required_without` bawaan `lang/id` sudah berbahasa Indonesia ("nama item wajib diisi bila paket tidak diisi") — cek hasilnya di test; override bila kaku.

`StorePosSaleRequest` **tidak** berubah (`catalog_item_id` tetap `required`).

### Controller / Action / Service

`Modules/Order/Requests/Concerns/ResolvesCatalogLines.php` — bentuk `lines()` diperluas:

```php
/** @return list<array{item: CatalogItem|null, name: string, unit_price: int, unit_cost: int|null, quantity: int}> */
public function lines(): array
{
    // baris katalog: item = model, name/unit_price/unit_cost dari katalog
    // baris custom : item = null, name/unit_price dari input, unit_cost = null
}

/** Σ unit_price × qty (katalog dan custom), sebelum diskon. */
public function subtotal(): int
```

Pemanggil `lines()` (`OrderController@store`, `@update` tahap TAMBAH, `PosController@store`) membaca `name`, `unit_price`, `unit_cost`, `catalog_item_id => $line['item']?->id` dari baris — bukan dari `$line['item']->…` lagi. Docblock trait diperbarui ("harga TIDAK diterima dari klien" → "harga katalog tidak diterima dari klien; harga custom diterima karena tidak ada sumber lain").

`UpdateOrderRequest::newTotal()` (1.2): baris baru custom memakai `unit_price` input. Tahap `after()` menambah cek aturan 4 untuk baris lama custom (`id` terisi, `catalog_item_id` tersimpan null): `name`/`unit_price` input harus sama dengan tersimpan.

`Modules/Finance/Services/SalesReport::topServices()`:
- Query saat ini `whereHas('catalogItem', type = service)` — baris custom (`catalog_item_id` null) **tidak terjaring**, dan `ServiceSales` mewajibkan `CatalogItem`. Tambah method terpisah, bukan mengubah bentuk DTO:

```php
/** Nilai item custom (tanpa katalog) dari order aktif — satu angka agregat. */
public function customItems(): CustomItemSales   // (baru) {orderCount, quantity, value}
```

Query: `OrderItem::whereNull('catalog_item_id')->whereHas('order', business_line != retail && work_status != cancelled)`. `ReportController@sales` menambah props `custom_items: {order_count, quantity, value} | null` (null bila nol — baris tidak dirender).

`orderProps()` dan `InvoiceController` props `items[]`: `catalog_item_id` sudah ditambahkan di 1.2 untuk `orderProps`; tambahkan juga ke invoice (`is_custom: bool` lebih jelas untuk halaman publik — pakai `is_custom` di kedua tempat agar konsisten, turunan `catalog_item_id === null`).

### Props Inertia

```ts
// order::index / order::edit — items[]
{ id; name; quantity; unit_price; catalog_item_id: number | null; unit_cost: number | null; is_custom: boolean }

// invoices.index / invoices.public — items[]
{ id; name; quantity; unit_price; is_custom: boolean }

// reports.sales
custom_items: { order_count: number; quantity: number; value: number } | null;
```

## Frontend

- `order-form.tsx` (1.2): `ItemRow` menambah `custom: boolean`, `name: string`, `unit_price: string`. Tombol "+ Item custom" di samping "Tambah item" — baris custom merender `Input` nama + `Input` harga (inputMode numeric, `hanyaDigit`) menggantikan `Select` paket; badge kecil "Custom". `transform` saat submit: baris katalog kirim `{id?, catalog_item_id, quantity}`; baris custom kirim `{id?, name, unit_price, quantity}` (tanpa `catalog_item_id`). `complete` → baris custom butuh nama non-kosong dan harga `!== ''`. Ringkasan kanan menghitung subtotal baris custom dari input.
- Mode edit: baris custom lama → nama & harga `disabled` (aturan 4) dengan tooltip "Ubah dengan menghapus baris lalu menambah yang baru"; qty tetap bisa diubah.
- `pages/index.tsx` Sheet detail tabel item: `Badge variant="outline"` "Custom" setelah nama bila `is_custom`.
- `components/invoice-document.tsx`: baris item custom **tanpa** badge (customer tidak perlu tahu), tetapi `types` menerima `is_custom` agar satu tipe `Invoice.items` dipakai di tiga tempat.
- `modules/finance/pages/reports/sales.tsx`: bila `custom_items` → baris terakhir tabel jasa, nama "Item custom", kategori "—", qty, nilai; caption "Item di luar katalog (harga nego) — tidak dibandingkan per paket."
