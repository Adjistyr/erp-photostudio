# 3.1 Pencarian + paginasi server-side

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 3 — Skala & jalan pintas harian | P2 | M | — | — |

## Tujuan

Daftar Order & Booking, Customer, dan Invoice memuat **semua baris sekaligus** (`OrderController@index` → `->get()`, `InvoiceController@index` → `->get()`, `CustomerController@index` → `SalesReport::customerSummaries()` memuat semua customer beserta ordernya). Pada < 10 transaksi/hari ini masih ringan, tapi dalam setahun daftar order menjadi ribuan baris: lambat dimuat dan tidak bisa dicari. Admin perlu menemukan "ORD-0412" atau "Budi" dalam satu ketikan.

## Lingkup

**Termasuk**
- Pencarian + filter + paginasi server-side di tiga daftar: `orders.index`, `customers.index`, `invoices.index`.
- Dua komponen bersama (baru): `resources/js/components/list-toolbar.tsx` dan `resources/js/components/pagination.tsx`.
- Value object (baru) `Modules\Shared\Http\ListQuery`.
- Tab lini di Order (sekarang `useState<Filter>` di klien) dipindah ke query string `line`.
- Index DB untuk pencarian customer.

**Tidak termasuk**
- Biaya, Kalender, Laporan — sudah per bulan (`?month=`).
- Katalog & Aset — < 50 baris, pencarian klien (3.6).
- Pembayaran (piutang) — daftar kecil, filter klien (3.2).
- Ekspor hasil filter — 4.5 memakai `ListQuery` yang sama.
- Pengurutan kolom (sort) — urutan tetap: order terbaru dulu; customer per nama.

## Aturan bisnis

1. Pencarian `q` cocok **tanpa membedakan huruf besar** pada: nomor order, nama customer, nomor HP customer (digit saja — `0812…` cocok dengan `+62 812…`).
2. Filter yang tersedia di Order: `line` (retail/studio/event), `status` (WorkStatus), `pay` (`unpaid|partial|paid`), `from`/`to` (rentang `service_date`). Invoice: `q`, `line`, `pay`. Customer: `q`, `line` (pernah bertransaksi di lini).
3. Filter status bayar **harus dievaluasi di SQL**, bukan setelah `paginate()` — status bayar adalah turunan (`Order::paymentStatus()`), dan menyaring setelah paginasi membuat halaman berisi < 25 baris dan `total` salah. Lihat Backend untuk query konkretnya.
4. Ukuran halaman tetap 25; `page` di luar rentang → halaman kosong dengan pesan, bukan 404.
5. Semua filter hidup di **URL** (`withQueryString()`), bukan state komponen: URL bisa dibagikan dan tombol kembali browser berfungsi.
6. Filter yang tidak valid (mis. `line=foo`) diabaikan, bukan error — URL sering diketik manual (konsisten dengan `Periods::orCurrent()`).
7. Nilai filter yang sedang aktif dikembalikan sebagai prop `filters` supaya toolbar menampilkan kondisi yang benar setelah reload.

```php

DB::statement('CREATE INDEX customers_phone_idx ON customers (phone)');

```

`orders(service_date)` sudah ada; `orders.number` sudah unique (ber-index). Tidak ada perubahan model.

Catatan desain: tidak memakai `pg_trgm`/full-text — tiga kolom pendek dengan ILIKE `%q%` pada ribuan baris masih < 10 ms; ekstensi butuh hak superuser di hosting yang belum diputuskan.

## Backend

### Route
Tidak ada route baru — `GET orders`, `GET customers`, `GET invoices` menerima query string.

### Request
Tidak memakai Form Request (GET tanpa validasi yang menggagalkan). Nilai dibaca lewat `ListQuery`:

```php
// Modules/Shared/Http/ListQuery.php (baru)
final readonly class ListQuery
{
    public function __construct(
        public string $q,          // trim, max 100 karakter, '' bila kosong
        public int $page,          // >= 1
        /** @var array<string, string> hanya kunci yang diizinkan & nilainya valid */
        public array $filters,
    ) {}

    /** @param array<string, list<string>|null> $allowed  kunci → daftar nilai sah (null = bebas) */
    public static function fromRequest(Request $request, array $allowed): self;

    public function has(string $key): bool;
    public function get(string $key): ?string;
    /** untuk prop `filters` dan `withQueryString` */
    public function toArray(): array;
    public function digits(): string;   // q hanya digit, untuk cocok HP
}
```

`fromRequest()` membuang nilai yang tidak ada di `$allowed` (aturan 6). Untuk `from`/`to` nilai dianggap sah bila `Carbon::canBeCreatedFromFormat($v, 'Y-m-d')`.

### Controller / Action / Service

**`OrderController@index`** — ganti `->get()` dengan builder berfilter:

```php
// `values()` belum ada di enum mana pun — tambahkan static `values(): array`
// (array_column(self::cases(), 'value')) di BusinessLine dan WorkStatus (baru).
$list = ListQuery::fromRequest($request, [
    'line'   => BusinessLine::values(),
    'status' => WorkStatus::values(),
    'pay'    => ['unpaid', 'partial', 'paid'],
    'from'   => null, 'to' => null,
]);

$orders = Order::with(['customer', 'items', 'payments', 'jobCosts'])
    ->search($list)              // scope (baru) di Order
    ->orderByDesc('id')          // bukan number: "ORD-10000" < "ORD-9999" (lihat Order::nextNumber)
    ->paginate(25)
    ->withQueryString();
```

Scope `Order::scopeSearch(Builder $q, ListQuery $list)` (baru) — satu tempat, dipakai Order, Invoice, dan 4.5:

```php
if ($list->q !== '') {
    $q->where(function (Builder $w) use ($list) {
        $w->where('number', 'ILIKE', "%{$list->q}%")
          ->orWhereHas('customer', function (Builder $c) use ($list) {
              $c->whereRaw('LOWER(name) LIKE ?', ['%'.mb_strtolower($list->q).'%']);
              if ($list->digits() !== '') {
                  $c->orWhereRaw("regexp_replace(COALESCE(phone, ''), '\D', '', 'g') LIKE ?", ['%'.$list->digits().'%']);
              }
          });
    });
}
if ($line = $list->get('line'))     $q->where('business_line', $line);
if ($status = $list->get('status')) $q->where('work_status', $status);
if ($from = $list->get('from'))     $q->whereDate('service_date', '>=', $from);
if ($to = $list->get('to'))         $q->whereDate('service_date', '<=', $to);

// Status bayar DI SQL (aturan 3). paid = Σ payments.amount; total = Σ qty*unit_price − discount.
if ($pay = $list->get('pay')) {
    $paid  = '(SELECT COALESCE(SUM(p.amount), 0) FROM payments p WHERE p.order_id = orders.id)';
    $total = '((SELECT COALESCE(SUM(i.quantity * i.unit_price), 0) FROM order_items i WHERE i.order_id = orders.id) - orders.discount)';
    match ($pay) {
        'unpaid'  => $q->whereRaw("$paid <= 0"),
        'partial' => $q->whereRaw("$paid > 0 AND $paid < $total"),
        'paid'    => $q->whereRaw("$paid >= $total"),
    };
}
```

Ketiga cabang **harus** menghasilkan himpunan yang sama dengan `Order::paymentStatus()` (`paid <= 0` → Unpaid; `paid < total` → Partial; sisanya Paid) — diuji di feature test dengan membandingkan ke perhitungan PHP.

**`InvoiceController@index`** — memakai scope yang sama (`allowed`: `line`, `pay`), tetap `where('work_status', '!=', Cancelled)`.

**`CustomerController@index`** — struktur sekarang (`SalesReport::customerSummaries()` memuat semua customer) harus dibalik: paginasi **customer** dulu, lalu ringkasan untuk 25 customer di halaman itu.
- `Customer::scopeSearch(Builder, ListQuery)` (baru): `LOWER(name) LIKE`, HP digit, dan `line` → `whereHas('orders', fn ($o) => $o->where('business_line', $line)->where('work_status', '!=', Cancelled))`.
- `SalesReport::customerSummaries(iterable $customers)` menerima koleksi customer (sudah eager-load `orders.items`, `orders.payments`) alih-alih memuat sendiri; pemanggil lain (Laporan Penjualan, kalau ada) menyesuaikan.
- Urutan: `orderBy('name')`.

### Props Inertia

Bentuk sama di tiga halaman:

```ts
interface Paginated<T> {
    data: T[];
    current_page: number;
    last_page: number;
    total: number;
    per_page: number;
}

// orders.index
{ orders: Paginated<OrderRow>; filters: { q: string; line?: string; status?: string; pay?: string; from?: string; to?: string } }
// invoices.index
{ invoices: Paginated<Invoice>; studio: Studio; filters: { q: string; line?: string; pay?: string } }
// customers.index
{ customers: Paginated<CustomerSummary>; sources: string[]; filters: { q: string; line?: string } }
```

Controller mengirim `->toArray()` dari paginator lalu memetakan `data` dengan `orderProps(...)`; hanya lima kunci di atas yang dikirim (bukan `links`/`path` bawaan Laravel — tidak dipakai klien).

## Frontend

**`components/list-toolbar.tsx` (baru)** — dua mode, satu komponen:

```ts
interface ListToolbarProps {
    /** Nilai awal dari props `filters` (mode server) atau state (mode klien). */
    value: { q: string } & Record<string, string | undefined>;
    /** Definisi filter Select; opsi `{value, label}`; kosong = hanya input cari. */
    filters?: { key: string; label: string; options: { value: string; label: string }[] }[];
    placeholder?: string;
    /** Mode server: dipanggil setelah debounce 300 ms dengan nilai lengkap → pemanggil melakukan router.get. */
    onChange: (next: ListToolbarProps['value']) => void;
    /** Mode server menampilkan jumlah hasil "123 order"; mode klien pemanggil hitung sendiri. */
    total?: { count: number; noun: string };
}
```

- Input cari dengan ikon `Search`, debounce 300 ms (hook kecil `useDebouncedCallback` di `hooks/use-debounced-callback.ts`, baru); `Select` per filter; tombol **Reset** muncul hanya bila ada nilai aktif.
- Komponen **tidak** memanggil `router` sendiri — pemanggil mode server menulis:
  ```ts
  router.get(ordersIndex().url, clean(next), { preserveState: true, preserveScroll: true, replace: true });
  ```
  (`clean()` membuang kunci kosong supaya URL rapi; `page` dihapus setiap filter berubah → kembali ke halaman 1.)

**`components/pagination.tsx` (baru)** — props `{ current_page, last_page, total, href: (page) => string }`; render "Hal. 2 dari 7 · 163 order", tombol ‹ › sebagai `Link` (`preserveScroll`), disembunyikan bila `last_page <= 1`.

**`modules/order/pages/index.tsx`**
- Hapus `useState<Filter>` dan `Tabs`; ganti dengan `ListToolbar` (filter: lini, status kerja, status bayar) + dua `<input type="date">` rentang di dalam toolbar (slot `children`).
- `orders.data` dipakai di tempat `orders` lama; `detail`/`paying` dicari dari `orders.data`.
- `KosongTabel`: `filters.q || ada filter aktif` → `kalimat="Tidak ada order yang cocok."` dengan `aksi={{label: 'Hapus filter', onClick: reset}}`; tanpa filter → kalimat lama.
- Setelah aksi dari Sheet (bayar, lanjut status), Inertia `back()` membawa query string karena URL halaman sudah mengandungnya — tidak perlu perubahan controller aksi.

**`modules/order/pages/invoices.tsx`** dan **`modules/customer/pages/index.tsx`**: pola sama; tab lini customer (`useState<Filter>`) dipindah ke `line`.

Teks UI: placeholder "Cari nomor, nama, atau HP…"; label filter "Lini", "Status kerja", "Status bayar", "Dari", "Sampai".
