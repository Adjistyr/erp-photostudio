# 2.3 Bukti bayar setelah catat bayar

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 2 — Bukti ke customer | P2 | S | 2.2 (flash `receipt`, `ReceiptSheet`, `useFlash`) | — |

## Tujuan

Setelah mencatat DP/pelunasan, admin tidak ditawari bukti untuk customer. Link invoice sudah mencerminkan pembayaran terbaru, jadi buktinya **ada** — hanya tidak muncul di akhir dialog *Catat Bayar*. Item ini memakai mekanisme 2.2 persis: flash `receipt` + `ReceiptSheet`.

## Lingkup

**Termasuk**
- Flash `receipt` dari `OrderPaymentController@store`.
- `PaymentDialog` menutup → `ReceiptSheet` terbuka dengan "Kirim bukti via WA / Salin link / Selesai".
- Props `receivables.index` menambah `customer_phone` dan `invoice_url` per baris (dipakai 2.4 juga).

**Tidak termasuk**
- Kwitansi sebagai dokumen terpisah dari invoice — satu dokumen (business-flow 5.5).
- Bukti saat **hapus** pembayaran — koreksi internal, tidak dikirim ke customer.
- Lampiran bukti transfer dari customer → 6.7.

## Aturan bisnis

1. Setiap `POST orders/{order}/payments` yang sukses menghasilkan flash `receipt` dengan `balance` dan `payment_status` **setelah** pembayaran dicatat.
2. Pesan WA bukti bayar menyebut nominal yang baru dicatat, sisa (bila ada), jatuh tempo (= `service_date`, bila sisa > 0), dan link invoice. Lunas → tanpa kalimat sisa/jatuh tempo, ditutup "Lunas, terima kasih!".
3. `ReceiptSheet` tampil di layar asal (`back()` tetap) — Detail Order maupun Pembayaran; tidak ada redirect baru.
4. Tanpa HP → tombol WA disabled, Salin link tetap (aturan 3 di 2.2).
5. Toast yang ada ("DP Rp X untuk ORD-… tercatat.") dipertahankan.

### Controller / Action / Service
`Modules/Order/Controllers/OrderPaymentController.php@store`
- Setelah `create()`, muat ulang `payments` (`$order->load('payments')` atau `$order->payments->push($payment)`) agar `balance()`/`paymentStatus()` memakai data terbaru, lalu:
  ```php
  Inertia::flash('receipt', [
      'order_id' => $order->id,
      'number' => $order->number,
      'total' => $order->total(),
      'balance' => $order->balance(),
      'payment_status' => $order->paymentStatus()->value,
      'invoice_url' => $order->invoiceUrl(),
      'print_url' => $order->invoiceUrl(print: true),
      'customer_phone' => $order->customer?->phone,
      'business_line' => $order->business_line->value,
      // Tambahan khusus bukti bayar — opsional di tipe Receipt:
      'paid_amount' => $amount,
      'paid_on' => $request->validated('paid_on'),
      'due_on' => $order->service_date->toDateString(),
  ]);
  ```
- `Receipt` TS: tiga field terakhir **opsional** (`paid_amount?: number; paid_on?: string; due_on?: string`) — hadir hanya dari jalur pembayaran; POS tidak mengirimnya.

`Modules/Order/Controllers/ReceivableController.php@index`
- Per baris tambah `'customer_phone' => $o->customer?->phone`, `'invoice_url' => $o->invoiceUrl()`. (`Receivables::open()` sudah eager-load `customer` — tidak ada N+1 baru.)

## Frontend

### `payment-dialog.tsx`
- Tidak menampilkan bukti sendiri — tetap `onSuccess: onClose` (dialog tertutup). Alasan: `ReceiptSheet` sudah mendengar flash lewat `useFlash` di halaman; menaruh langkah kedua di dalam dialog berarti dua komponen menangani payload yang sama.
- Pratinjau "jadi Lunas / DP 60%" tetap.

### `receipt-sheet.tsx` (dari 2.2)
- Mode ditentukan dari payload: `paid_amount !== undefined` → header "Pembayaran tercatat", baris "Diterima {formatRp(paid_amount)} · {formatTanggal(paid_on)}", lalu sisa + `PaymentBadge`; tombol WA berlabel **Kirim bukti**.
- Pesan: fungsi `paymentReceiptMessage(receipt, studio)` di `invoice-document.tsx`:
  `Halo Kak, pembayaran {formatRp(paid_amount)} untuk {number} sudah kami terima {formatTanggal(paid_on)}.` + (sisa > 0 ? ` Sisa {formatRp(balance)}, jatuh tempo {formatTanggal(due_on)}. Pembayaran ke {studio.bank_account}.` : ` Lunas, terima kasih!`) + `\nRincian: {invoice_url}`. Nama depan tidak tersedia di flash (hanya HP) — "Kak" sebagai sapaan netral, sama dengan fallback di `whatsappMessage()`.

### Halaman pemanggil
- `receivables.tsx` dan `modules/order/pages/index.tsx`: tambah `useFlash<Receipt>('receipt')` + `<ReceiptSheet … />`; keduanya perlu `studio` di props → `ReceivableController@index` dan `OrderController@index` menambah `'studio' => config('studio')`.
