# 2.2 Struk setelah transaksi POS

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 2 — Bukti ke customer | P1 | M | 2.1 (HP customer) | — |

## Tujuan

Setelah *Simpan & Bayar* admin tidak punya apa pun untuk diberikan ke customer: toast hilang dalam beberapa detik, tidak ada nomor transaksi yang bisa disalin, tidak ada struk cetak atau WA. Halaman publik invoice bertanda tangan (`invoices.public`, `/i/{order}`) sudah menampilkan kondisi terkini — struk retail **adalah** invoice retail yang lunas. Yang kurang hanya menawarkannya di akhir alur.

## Lingkup

**Termasuk**
- Flash `receipt` dari `PosController@store` + hook klien `useFlash()` (baru) untuk membacanya.
- Sheet "Transaksi tersimpan" di POS: nomor, total, Cetak, Kirim WA, Salin link, Transaksi baru.
- Halaman publik: judul "Struk" untuk retail, CSS cetak 80 mm, `?print=1` memanggil dialog cetak saat halaman terbuka.

**Tidak termasuk**
- Printer thermal langsung (ESC/POS, Bluetooth) — print browser ke printer 80 mm sudah cukup; integrasi driver = proyek sendiri.
- Struk untuk pembayaran DP/pelunasan non-retail → 2.3 (memakai flash dan Sheet pola yang sama).
- Mengubah isi `InvoiceDocument` selain judul & lebar cetak.
- Daftar transaksi hari ini → 2.5.

## Aturan bisnis

1. Struk hanya tampil **sekali** setelah simpan (flash, bukan props) — refresh halaman tidak memunculkannya lagi; struk lama diakses lewat 2.5 atau Invoice.
2. Link struk = `Order::invoiceUrl()` (signed, tanpa kedaluwarsa) — tidak ada URL baru. Isinya selalu kondisi terkini.
3. "Kirim WA" hanya aktif bila order punya customer **dengan HP**; walk-in tanpa HP → tombol disabled dengan keterangan, Salin link tetap bisa.
4. Order retail di halaman publik diberi judul **"Struk"** dan nomor `invoiceNumber()` tetap `INV-xxxx` (satu penomoran; struk bukan dokumen terpisah). Studio/event tetap "Invoice".
5. `?print=1` hanya memicu `window.print()` sekali saat halaman dimuat; tanpa parameter perilaku sekarang (tombol Cetak manual) tidak berubah.
6. Keranjang tetap dikosongkan saat sukses (perilaku sekarang) — Sheet struk tidak menahan transaksi berikutnya; "Transaksi baru" hanya menutup Sheet.

## Perubahan data

Tidak ada migrasi.

## Backend

### Route
Tidak ada route baru. `invoices.public` menerima query `print` (opsional) — `signed` middleware memvalidasi tanda tangan atas URL **tanpa** parameter tambahan? **Tidak** — `URL::signedRoute` menandatangani seluruh query; menambah `?print=1` ke URL yang sudah ditandatangani membuatnya **invalid**. Oleh karena itu:
- `Order::invoiceUrl(bool $print = false): string` → `URL::signedRoute('invoices.public', array_filter(['order' => $this->id, 'print' => $print ? 1 : null]))`. Dua URL berbeda, keduanya sah; `print_url` dikirim terpisah di flash.
- Catat di `docs/development.md` gotcha: *signed URL tidak bisa ditambahi query di klien*.

### Request
Tidak ada.

### Controller / Action / Service
`Modules/Order/Controllers/PosController.php@store`
- Setelah transaksi, selain toast yang ada, tambah:

`Modules/Order/Controllers/InvoiceController.php@show`

- `invoiceProps()` menambah `print_url => $o->invoiceUrl(print: true)` (dipakai 2.5 dan Invoice).

### Props Inertia

## Frontend

### Hook `useFlash` (baru) — `resources/js/hooks/use-flash.ts`
Generalisasi pola `use-flash-toast.ts` (`router.on('flash', …)`): `useFlash<T>(key: string): [T | null, () => void]` — menyimpan payload flash `key` di state, mengembalikan fungsi `clear`. `use-flash-toast.ts` **tidak** diubah (toast tetap global). Catatan desain: flash Inertia 3 datang lewat event, bukan `usePage().props`, sehingga state lokal diperlukan agar Sheet tetap terbuka setelah event lewat.

### Sheet struk — `resources/js/modules/order/components/receipt-sheet.tsx` (baru)
Props `{ receipt: Receipt | null; studio: Studio; onClose: () => void }`. Dipakai `pos.tsx` (2.2), `receivables.tsx` & `index.tsx` lewat `PaymentDialog` (2.3), dan 2.5.
- Header: "Transaksi tersimpan" (retail) / "Pembayaran tercatat" (lainnya, 2.3); `SheetTitle` nomor order `font-mono text-2xl`.
- Isi: total `formatRp`; untuk `balance > 0` tampilkan "Sisa Rp X" dan `PaymentBadge`.
- Tombol (urutan): **Cetak** (`<a href={print_url} target="_blank">`, `nativeButton={false}` + `render=` sesuai pola Base UI), **Kirim WA** (`wa.me/{keNomorWa(phone)}?text=…`, disabled bila `customer_phone` null dengan teks bantu "Customer belum punya nomor HP — salin link dan kirim manual", sama dengan kalimat di `invoices.tsx`), **Salin link** (`navigator.clipboard.writeText(invoice_url)` + `toast.success('Link struk disalin')`), **Transaksi baru / Selesai** (`variant="ghost"`, `onClose`).
- Pesan WA struk (retail): `Terima kasih sudah berbelanja di {studio.name}! Struk {number} · total {formatRp(total)}. Lihat/unduh: {invoice_url}` — fungsi `receiptMessage(receipt, studio)` di `invoice-document.tsx` bersebelahan dengan `whatsappMessage()`. Setelah 2.4 kedua pesan berasal dari template; untuk retail cukup teks tetap ini (keputusan K5 berlaku untuk pesan **tagihan**).

### `pos.tsx`
- `const [receipt, clearReceipt] = useFlash<Receipt>('receipt')`; render `<ReceiptSheet receipt={receipt} studio={studio} onClose={clearReceipt} />` di luar grid utama (sejajar `Head`).
- `PosController@index` perlu mengirim `studio => config('studio')` (belum ada di props POS) untuk nama studio di pesan WA.
- `onSuccess` yang ada (reset form + search) tidak berubah.

### `invoice-public.tsx`
- Judul dokumen & `<Head>`: `invoice.business_line === 'retail' ? 'Struk' : 'Invoice'`; teks "Struk" juga dipakai di heading `InvoiceDocument` lewat prop baru `title?: string` (default "Invoice").
- `useEffect(() => { if (auto_print) window.print(); }, [auto_print])`.
- Retail: `<main className="… print:max-w-[80mm]">` + `<style>{'@page { size: 80mm auto; margin: 4mm }'}</style>` dirender **hanya** bila retail (inline `<style>` karena `@page` tidak bisa per-elemen lewat Tailwind). Non-retail tetap A4 default browser.
- Tombol Cetak manual yang ada tetap (`print:hidden`).
