# 6.3 Bundel katalog (paket dengan komponen)

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 6 — Aset & lainnya | P3 | L | 1.1 (`ServiceCategory`) | — |

## Tujuan

"Paket Studio 1 Jam termasuk 5 cetak 4R": HPP bahan cetaknya ikut terhitung ke margin paket, tanpa admin menambah baris cetak manual (yang membuat total order salah karena cetak jadi tertagih dua kali).

Bangun hanya kalau owner mulai mengeluhkan margin paket studio yang tampak terlalu tinggi karena HPP bahan diabaikan.

## Lingkup

**Termasuk** — relasi komponen pada item katalog jasa; HPP bundel dihitung dari komponen; saat masuk order, satu baris bundel dengan `unit_cost` hasil hitung; tampilan komponen di Katalog dan di detail order.

**Tidak termasuk** — bundel bersarang (komponen adalah bundel); komponen jasa (hanya produk, karena jasa tidak punya HPP tetap); mengurangi stok (tidak dilacak); harga bundel otomatis dari komponen (harga tetap diketik owner).

## Aturan bisnis

1. Hanya item `type = service` yang boleh punya komponen; komponen harus `type = product` dan aktif saat ditambahkan.
2. HPP bundel = Σ (`component.unit_cost × quantity`) **saat transaksi** — disalin ke `order_items.unit_cost` seperti produk biasa (snapshot). Katalog **tidak** menyimpan HPP bundel.
3. `CatalogItemRequest` tetap melarang `unit_cost` untuk jasa — bundel adalah jasa yang HPP-nya **dihitung**, bukan diketik.
4. Komponen yang dinonaktifkan tetap dihitung di HPP bundel (katalog nonaktif hanya menyembunyikan dari pilihan); dihapus dari bundel = benar-benar dihapus.
5. Laporan Penjualan: bundel tetap muncul di bagian jasa dengan kolom HPP bahan terisi (sekarang "—").
6. Invoice ke customer menampilkan komponen sebagai sub-baris tanpa harga ("termasuk 5× Cetak 4R").

## Perubahan data

Tabel (baru) `catalog_bundle_items`: `id`, `bundle_id` FK `catalog_items` cascadeOnDelete, `component_id` FK `catalog_items` restrictOnDelete, `quantity` unsignedInteger ≥ 1, unique (`bundle_id`,`component_id`). `order_items`: tambah `components` json nullable — snapshot `[{name, quantity, unit_cost}]` supaya invoice & detail order tidak bergantung pada katalog yang berubah.

`CatalogItem`: relasi `components(): BelongsToMany` (pivot `quantity`), `bundleCost(): ?int` (null bila bukan bundel), `isBundle(): bool`.

## Backend

### Route
| Method | Path | Name | Handler |
|---|---|---|---|
| PUT | `catalog/{catalogItem}/components` | `catalog.components.update` | `CatalogItemController@updateComponents` (baru) — mengganti seluruh daftar |

### Request
`UpdateBundleComponentsRequest` (baru): `components` array max:20; `components.*.component_id` exists `catalog_items` where `type = product`; `components.*.quantity` integer 1–99; `withValidator`: item target harus jasa; komponen tidak boleh item itu sendiri.

### Controller / Service
- `updateComponents` → `sync()` pivot, toast "Komponen {nama} diperbarui. Berlaku untuk order berikutnya."
- `ResolvesCatalogLines::lines()` (Order): untuk jasa dengan komponen, `unit_cost = bundleCost()`, `components` = snapshot.
- `SalesReport` jasa: `cost` dari `order_items.unit_cost` (sudah ada untuk produk — pastikan jasa memakai jalur yang sama).
- `CatalogItemController@index` props: `components: [{id, name, quantity, unit_cost}]`, `bundle_cost`.

### Props Inertia
```ts
// catalog item
components: { id: number; name: string; quantity: number; unit_cost: number | null }[]; bundle_cost: number | null;
// order item
components: { name: string; quantity: number; unit_cost: number | null }[] | null;
```

- Detail order & `InvoiceDocument`: sub-baris komponen (indent, abu-abu, tanpa harga).

## Penyimpangan (kode yang menang)

Dibangun atas permintaan user walau catatan "bangun hanya kalau owner mengeluh" belum terpenuhi.

- **Komponen = produk, bukan varian** (keputusan). `component_id` merujuk `catalog_items` bertipe produk. Produk bervarian memakai `catalog_items.unit_cost`, yang sejak 7.3 disalin dari varian aktif termurah — cukup untuk HPP bahan paket dan menjaga unique (`bundle_id`,`component_id`) tetap sederhana. Bila suatu saat paket harus memakai varian tertentu (mis. bingkai A4 Kayu), tambah `component_variant_id` nullable.
- **UI di halaman Edit, bukan dialog.** Sejak 7.2 tambah/edit katalog adalah halaman penuh; komponen menjadi bagian "Komponen paket" (`#komponen`) dengan tombol Simpan komponen sendiri (seperti galeri foto). Menu baris jasa di daftar Katalog "Komponen…" membuka bagian itu. Jasa baru: komponen bisa ditambahkan setelah disimpan.
- **Aturan 1 "aktif saat ditambahkan"**: produk nonaktif ditolak hanya bila belum ada di paket; komponen lama yang kemudian dinonaktifkan boleh tetap disimpan ulang (aturan 4). Paket dirinya sendiri & qty 1–99 divalidasi; produk dobel ditolak (`distinct`).
- **Bersarang dicegah juga lewat ubah jenis**: `CatalogItemRequest` menolak produk-komponen diubah jadi jasa dan paket berkomponen diubah jadi produk.
- **Props tambahan**: komponen katalog membawa `is_active`; halaman form menerima `component_options` (produk aktif + komponen nonaktif paket itu); opsi Form Order membawa `components: {name, quantity}[]` (tanpa HPP) untuk keterangan "termasuk …" di baris baru; invoice menerima `components: {name, quantity}[]` tanpa `unit_cost`.
- **Snapshot per 1 paket**: `order_items.components[].quantity` = qty per paket; tampilan (detail order, invoice, form order) mengalikan dengan qty baris ("2 paket → 10× Cetak 4R").
- **Laporan Penjualan**: tabel jasa sebelumnya tidak punya kolom HPP — kolom "HPP bahan" ditambahkan (`services[].cost`, null → "—"), dijumlah dari `order_items.unit_cost` baris jasa.
- **Margin Katalog** untuk paket tetap "—": selisih harga − HPP bahan bukan margin jasa (biaya job belum masuk). Margin order (Detail Order, Margin per Lini) otomatis ikut berkurang karena `Order::materialCost()` membaca `order_items.unit_cost`.
- **POS** hanya menjual produk, jadi tidak pernah membuat baris paket; jalurnya tetap menyimpan `components` dari `lines()` (selalu null).
- **Test 422**: test request memakai redirect + `assertSessionHasErrors` seperti test Katalog lain (Inertia), bukan status 422 JSON.
