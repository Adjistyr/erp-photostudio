# 4.2 Retur / refund

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 4 — Kenyamanan transaksi | P2 | M | 0.1 (`created_by`), 0.2 (`RecordOrderEvent`), 3.3 (`CashReceipts`) | K3 |

## Tujuan

Uang yang dikembalikan ke customer (cetak salah lalu diganti, DP order batal yang owner putuskan dikembalikan) tercatat sebagai **uang keluar pada hari pengembalian** — tanpa menghapus pembayaran lama yang bulannya mungkin sudah tutup buku, dan tanpa membuat order menggantung sebagai piutang.

## Lingkup

**Termasuk**
- Tabel `refunds`, catat & hapus refund dari Sheet detail order, event `refunded`.
- Penyesuaian perhitungan: margin, Laba Rugi, Kas Harian, invoice publik.
- Semua lini (K3).

**Tidak termasuk**
- Retur **per item** (barang mana yang dikembalikan) — refund adalah nominal; HPP item yang dikembalikan tetap terhitung (cetakan yang salah memang jadi limbah). `// ponytail: refund nominal, bukan per item`.
- Status kerja baru (`refunded`) — status kerja menggambarkan pekerjaan, bukan uang; order tetap `delivered`/`cancelled`.
- Mengembalikan barang ke stok — stok tidak dilacak (business-flow).
- Refund otomatis saat pembatalan — pembatalan tetap "DP hangus" secara default; refund dicatat terpisah bila owner memutuskan.

## Aturan bisnis

1. Refund hanya untuk order yang **punya pembayaran**: `amount` ≤ `totalPaid() − totalRefunded()`; melebihi → 422 "Pengembalian melebihi uang yang diterima (sisa Rp X)".
2. `amount` > 0, `reason` wajib (maks 255), `method` salah satu `PaymentMethod` (`cash`/`transfer`/`qris`) — menyatakan dari kas mana uang keluar.
3. `refunded_on` wajib, tidak boleh di masa depan, dan bulannya **belum tutup buku** (`OpenPeriod`). Pembayaran asli **tidak** disentuh — boleh di bulan yang sudah tertutup.
4. Hapus refund = koreksi salah catat (pola `ConfirmDelete`), hanya bila bulan `refunded_on` masih terbuka (`OpenPeriod::ensureOpen`).
5. Refund mengurangi **omzet bulan refund** (basis kas), bukan bulan pembayaran asli.
6. Refund **tidak** membuat order kembali berpiutang: sisa tagihan tetap `total − totalPaid` (bruto). Customer tidak berutang karena uangnya dikembalikan.
7. Setiap catat/hapus refund → `RecordOrderEvent($order, 'refunded', ['amount' => …, 'method' => …, 'reason' => …])` (hapus: `['deleted_refund_id' => …, 'amount' => …]` dengan tipe yang sama; cukup satu tipe karena jarang).

### Dampak ke perhitungan (wajib diikuti, ini inti PR)

| Perhitungan | Lokasi | Pakai refund? | Alasan |
|---|---|---|---|
| `totalPaid()` | `Order` | **Tidak berubah** (bruto) | Dasar piutang dan status bayar; uang memang pernah diterima |
| `totalRefunded()` (baru) | `Order` | — | `Σ refunds.amount`; relasi `refunds` wajib eager-load seperti `payments` |
| `netPaid()` (baru) | `Order` | — | `totalPaid() − totalRefunded()` — uang yang benar-benar tinggal di kas |
| `balance()` | `Order` | **Tidak** | Aturan 6; kalau pakai `netPaid()`, order yang direfund penuh muncul lagi di Pembayaran sebagai piutang — salah |
| `paymentStatus()` | `Order` | **Tidak** | Turunan dari `balance()`; order tetap "Lunas". Tanda refund ditampilkan terpisah (badge "Retur Rp X") |
| `paidRatio()` | `Order` | **Tidak** | Mengikuti `paymentStatus()` |
| `margin()` | `Order` | **Ya** | Non-batal: `total() − totalRefunded() − directCost()`; batal: `netPaid() − directCost()`. Omzet riil order berkurang sebesar refund |
| `Receivables::open()` | Finance | **Tidak** | Memakai `balance()` — tidak berubah (aturan 6) |
| `ProfitAndLoss::revenue()` | Finance | **Ya** | `Σ payments(paid_on ∈ bulan) − Σ refunds(refunded_on ∈ bulan)`, per lini bila `$line` diisi (`whereHas('order')` sama seperti payments). Dipakai Laba Rugi, Margin per lini, Dashboard, Bagi Hasil |
| `ProfitAndLoss::materialCosts()` | Finance | **Tidak** | HPP tetap diakui pada bulan pembayaran; retur tidak mengembalikan bahan |
| `SalesReport::topProducts()` | Finance | **Tidak** | Qty per produk dari item; refund bukan per item (lihat Tidak termasuk). Catat di caption laporan: "belum dikurangi retur" |
| `CashReceipts` (3.3) | Finance | **Ya** | Baris refund negatif per `method` per hari; total per metode = masuk − keluar |
| Dashboard `revenue` | app | **Ya** (lewat `pnl->revenue`) | Tidak ada perubahan kode di controller |
| Invoice publik | Order | **Tampil** | Bagian "Pengembalian" di bawah pembayaran bila ada; "Sisa tagihan/Lunas" tetap dari `balance()` |

## Perubahan data

Migrasi `2026_10_xx_000001_create_refunds_table.php`:

```php
Schema::create('refunds', function (Blueprint $table) {
    $table->id();
    $table->foreignId('order_id')->constrained()->restrictOnDelete();
    $table->date('refunded_on');          // tanggal uang keluar — basis kas
    $table->bigInteger('amount');
    $table->string('method');             // PaymentMethod — dari kas mana
    $table->string('reason');
    $table->foreignId('created_by')->nullable()->constrained('users')->nullOnDelete();
    $table->timestamps();
    $table->index('refunded_on');
});
```

Model `Modules\Order\Models\Refund` (baru): casts `refunded_on` immutable_date, `amount` integer, `method` `PaymentMethod`; trait `RecordsCreator` (0.1). `Order`: relasi `refunds(): HasMany`, `totalRefunded()`, `netPaid()`, `margin()` diubah; docblock `@property-read Collection<int, Refund> $refunds`; komentar di `margin()` diperbarui (menyebut refund).

## Backend

### Route
`Modules/Order/Routes/web.php`, dalam grup auth:
- `POST orders/{order}/refunds` → `OrderRefundController@store` (baru) → `orders.refunds.store`
- `DELETE orders/{order}/refunds/{refund}` → `OrderRefundController@destroy`, `->scopeBindings()` → `orders.refunds.destroy`

### Request
`Modules\Order\Requests\StoreRefundRequest` (baru):
- `refunded_on`: `required|date_format:Y-m-d|before_or_equal:today`, `new OpenPeriod`
- `amount`: `required|integer|min:1`
- `method`: `required`, `Rule::enum(PaymentMethod::class)`
- `reason`: `required|string|max:255`
- `after()`: bila tanpa error lain, `amount > $order->totalPaid() − $order->totalRefunded()` → error di `amount` dengan sisa yang bisa dikembalikan (`Money::format`). Order diambil dari `$this->route('order')` dengan `load(['payments','refunds'])`.
- `attributes()`: tanggal pengembalian, jumlah, metode, alasan.

### Controller / Action / Service
`OrderRefundController` (baru), pola sama dengan `OrderPaymentController`:
- `store`: `DB::transaction` → `$order->refunds()->create($request->validated())` → `RecordOrderEvent` → `Inertia::flash('toast', …)` → `back()`.
- `destroy(Order $order, Refund $refund)`: `OpenPeriod::ensureOpen($refund->refunded_on)` → hapus → event → `back()`.
- `ProfitAndLoss::revenue()`: kurangi `Refund::query()->whereBetween('refunded_on', …)->when($line, …)->sum('amount')`.
- `OrderController::index/calendar`, `InvoiceController`, `ReceivableController`, `DashboardController`, `Receivables`, `ProfitAndLoss::materialCosts` — tambah `refunds` ke setiap `with([... 'payments' ...])` supaya `margin()`/props tidak N+1 (cari semua `'payments'` di `with(`).

### Props Inertia
`orderProps()` dan `invoiceProps()` menambah:

```ts
refunds: { id: number; refunded_on: string; amount: number; method: PaymentMethod; reason: string; created_by_name: string | null }[];
total_refunded: number;
refundable: number; // totalPaid − totalRefunded; 0 → tombol Catat Retur disembunyikan
```

`margin` sudah ada — nilainya berubah mengikuti aturan.
