# 6.7 Lampiran bukti transfer pada pembayaran

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 6 — Aset & lainnya | P3 | M | Hosting & storage diputuskan (go-live) | — |

## Tujuan

Pembayaran transfer/QRIS yang dicatat admin bisa dicek owner dari screenshot mutasi tanpa membuka WhatsApp customer lagi. Baru berarti saat owner bukan lagi orang yang mencatat (setelah 5.1).

## Lingkup

**Termasuk** — satu gambar opsional per pembayaran (unggah saat catat bayar), tampil di detail order & Pembayaran lewat URL bertanda tangan; disk privat.

**Tidak termasuk** — OCR/pencocokan otomatis dengan mutasi bank; lampiran untuk tunai; mengganti lampiran (pembayaran tidak diedit — hapus & catat ulang); lampiran untuk biaya/servis (pola sama, tambah belakangan bila perlu).

## Aturan bisnis

1. Opsional; hanya `method ∈ {transfer, qris}` (tunai → ditolak).
2. Format `jpg|jpeg|png|webp|pdf`, ≤ 2 MB; disimpan di disk `local` (root `storage/app/private`, **bukan** publik) dengan nama acak; path di `payments.proof_path`.
3. Dibuka hanya oleh user login lewat route bertanda tangan sementara (`temporarySignedRoute`, 10 menit) — bukan URL publik; invoice publik **tidak** menampilkan bukti.
4. Hapus pembayaran (koreksi) → file ikut dihapus (`deleted` observer); gagal hapus file tidak membatalkan transaksi (log warning).
5. Hosting: butuh disk persisten atau S3-compatible; kalau deploy container tanpa volume, ganti `FILESYSTEM_DISK` — alasan item ini menunggu keputusan hosting.

## Perubahan data

Migrasi `add_proof_path_to_payments`: `proof_path` string nullable. `Payment`: fillable + docblock; `hasProof(): bool`; `proofUrl(): ?string` (temporary signed).

## Backend

### Route
| Method | Path | Name | Handler |
|---|---|---|---|
| GET | `payments/{payment}/proof` | `payments.proof` | `Modules\Order\Controllers\PaymentProofController@show` (baru) — middleware `auth`, `verified`, `signed` → `Storage::disk('local')->response($path)` |

### Request
`StorePaymentRequest` (dan `StorePosSaleRequest` bila dipakai untuk transfer/QRIS): `proof` nullable `file|mimes:jpg,jpeg,png,webp,pdf|max:2048`, `prohibited_if:method,cash`. Attributes "bukti transfer". Form dikirim sebagai `multipart` (`useForm` + `forceFormData: true`).

### Controller
`OrderPaymentController@store`: `proof_path = $request->file('proof')?->store('payment-proofs', 'local')`. `destroy`: hapus file setelah commit (`DB::afterCommit`). `orderProps().payments[]` dan props Pembayaran: `proof_url` (null bila tidak ada).

### Props Inertia
```ts
proof_url: string | null;   // payments[]
```

## Frontend

- `PaymentDialog`: field unggah (`<input type="file" accept=…>`) muncul hanya saat metode transfer/QRIS; pratinjau nama file + ukuran; error ukuran dari server.
- Baris pembayaran di Sheet detail & tabel Pembayaran: ikon klip → membuka `proof_url` di tab baru (gambar/PDF langsung). Tanpa lampiran → tidak ada ikon.
