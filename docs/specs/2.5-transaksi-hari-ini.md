# 2.5 Panel "Transaksi hari ini" di POS

| Fase | Prioritas | Estimasi | Prasyarat | Keputusan |
|---|---|---|---|---|
| 2 — Bukti ke customer | P2 | S | 2.2 (`ReceiptSheet`, `print_url`) | — |

## Tujuan

"Tadi yang Rp 80 ribu sudah tercatat belum?" hari ini dijawab dengan pindah ke Order & Booking dan memfilter Retail. Admin di meja kasir butuh daftar transaksi hari ini **di layar POS**, sekaligus jalan untuk membuka ulang struk (2.2) yang flash-nya sudah lewat.

## Lingkup

**Termasuk**
- Props `today_sales` di `PosController@index`.
- Panel ringkas (collapsible) di kolom kanan POS dengan tombol struk per baris.

**Tidak termasuk**
- Rentang tanggal lain / pencarian — itu Order & Booking (3.1).
- Void/retur dari panel ini → 4.2.
- Total per metode bayar untuk tutup hari → 3.3 (Kas Harian); panel ini hanya total hari ini.

## Aturan bisnis

1. "Hari ini" = order retail dengan `service_date = today()` (POS selalu menulis `service_date` hari transaksi), urut terbaru (`created_at desc`), maksimal 50 baris — di atas itu bukan skala POS ini; caption menyebut "50 terbaru".
2. Order batal tetap ditampilkan dengan tanda (status Batal) supaya hitungan "sudah tercatat?" tidak menyesatkan; **total** panel hanya menjumlahkan yang tidak batal.
3. Tombol struk per baris membuka `ReceiptSheet` yang sama dengan 2.2, diisi dari data baris (bukan flash). Order batal: tombol struk disembunyikan (halaman publik 404 untuk order batal).
4. Panel tertutup secara default saat kosong; terbuka otomatis bila ada ≥ 1 transaksi? **Tidak** — tetap tertutup, header menampilkan ringkasan ("Hari ini · 7 transaksi · Rp 1.250.000") sehingga informasi utama terbaca tanpa membuka. Alasan: kolom kanan dipakai keranjang; panel terbuka mendorong tombol *Simpan & Bayar* ke bawah layar.
5. Panel diperbarui setelah transaksi tersimpan tanpa aksi tambahan (Inertia me-reload props halaman pada redirect `to_route('pos.index')`).

### Controller / Action / Service
`Modules/Order/Controllers/PosController.php@index`
```php
$today = today()->toDateString();
$sales = Order::with(['customer', 'items', 'payments'])
    ->where('business_line', BusinessLine::Retail)
    ->whereDate('service_date', $today)
    ->latest('id')
    ->limit(50)
    ->get();

'today_sales' => $sales->map(fn (Order $o) => [
    'id' => $o->id,
    'number' => $o->number,
    'time' => $o->created_at?->format('H:i'),
    'items_summary' => $o->itemsSummary(),
    'total' => $o->total(),
    'method' => $o->payments->first()?->method->value,   // POS = satu pembayaran; setelah 4.4 bisa 2 → kirim array
    'cancelled' => $o->isCancelled(),
    'customer_name' => $o->customer?->name,
    'customer_phone' => $o->customer?->phone,
    'invoice_url' => $o->isCancelled() ? null : $o->invoiceUrl(),
    'print_url' => $o->isCancelled() ? null : $o->invoiceUrl(print: true),
])->values()->all(),
'today_total' => $sales->reject(fn (Order $o) => $o->isCancelled())->sum(fn (Order $o) => $o->total()),
```
- `created_at` di-cast `Carbon` default; `time` memakai zona waktu app — `config/app.php` sudah `Asia/Jakarta` (default `APP_TIMEZONE`), jadi jam benar tanpa perubahan.
- Tidak memakai `orderByDesc('number')` seperti `OrderController@index` karena `number` string (`ORD-10000` < `ORD-9999`); `latest('id')` benar dan sudah dipakai `Order::nextNumber()`.

## Frontend

`resources/js/modules/order/pages/pos.tsx`
- Di kolom kanan (`lg:grid-cols-[1fr_22rem]`, di bawah kartu keranjang): `Collapsible` (`components/ui/collapsible.tsx`, sudah ada) dengan trigger `Button variant="ghost"` berisi `ChevronDown` + "Hari ini · {n} transaksi · {formatRp(today_total)}". Kosong → trigger tetap tampil "Hari ini · belum ada transaksi" dan disabled.
- Isi: tabel ringkas (`TabelData`): Jam · No (`SelKode`) · Item (`truncate max-w-32`, `title`) · Metode (`PAYMENT_METHOD_LABEL`) · Total (`SelUang`) · tombol ikon `Receipt` (lucide) `aria-label="Buka struk"`. Baris `cancelled` → `opacity-60` + badge "Batal", tanpa tombol struk.
- Klik struk → `setReceipt({ order_id, number, total, balance: 0, payment_status: 'paid', invoice_url, print_url, customer_phone, business_line: 'retail' })` → `ReceiptSheet` yang sudah dipasang 2.2. Implementasi: `ReceiptSheet` menerima `receipt` dari state gabungan `flashReceipt ?? manualReceipt`; `onClose` membersihkan keduanya.
- Caption: "Menampilkan 50 transaksi terbaru hari ini. Semua order ada di Order & Booking." dengan `Link` ke `orders.index`.
